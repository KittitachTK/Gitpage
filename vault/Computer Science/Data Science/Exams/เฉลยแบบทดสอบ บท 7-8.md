### Q01 · ข้อใดอธิบาย ML และความสัมพันธ์กับ AI ได้ถูกต้องที่สุด
> A. ML เป็นส่วนหนึ่งของ AI ที่ใช้ข้อมูลเรียนรู้แบบแผนเพื่อทำงาน เช่น การทำนาย
> B. AI เป็นส่วนหนึ่งของ ML และทุกระบบ AI ต้องฝึกจากข้อมูลเสมอ
> C. ML คือการเขียนกฎทุกกรณีด้วยมือ โดยไม่ใช้ข้อมูลเรียนรู้
> D. ML หมายถึงระบบที่สร้างข้อความสนทนาเท่านั้น

**✅ คำตอบ: A**

**เหตุผล:** AI คือเป้าหมายกว้าง ๆ ที่ให้เครื่องทำงานที่ต้องใช้ "ความฉลาด" ส่วน ML เป็น **วิธีหนึ่ง** ในการสร้าง AI โดยให้เครื่อง **เรียนรู้แบบแผนจากข้อมูล** แทนการเขียนกฎเอง ความสัมพันธ์จึงเป็น AI ⊃ ML (⊃ Deep Learning)

**ทำไมข้ออื่นผิด**
- **B** กลับด้านความสัมพันธ์ และ AI ไม่จำเป็นต้องฝึกจากข้อมูลเสมอ เช่น ระบบผู้เชี่ยวชาญแบบกฎ (rule-based) ก็นับเป็น AI
- **C** การเขียนกฎทุกกรณีด้วยมือคือ rule-based programming ซึ่งตรงข้ามกับ ML
- **D** ระบบสร้างข้อความ (เช่น LLM) เป็นเพียง **ส่วนหนึ่ง** ของ ML ML ยังรวมการทำนายตัวเลข การจำแนก การจัดกลุ่ม ฯลฯ

### Q02 · อีเมลเก่า 2,000 ฉบับ ระบุแล้วว่า "สแปม/ไม่ใช่สแปม" ต้องการทำนายประเภทอีเมลใหม่ เป็นการเรียนรู้แบบใด
> A. Unsupervised: clustering B. Supervised: classification C. Supervised: regression D. Reinforcement learning

**✅ คำตอบ: B**

**เหตุผล:** ใช้หลัก 2 คำถาม
1. **มี label หรือไม่?** มี (แต่ละฉบับถูกระบุแล้ว) → **Supervised**
2. **สิ่งที่ทำนายเป็นอะไร?** เป็น **ประเภท** (สแปม / ไม่ใช่) → **Classification** (แบบ binary)

**ทำไมข้ออื่นผิด**
- **A** clustering ใช้เมื่อ **ไม่มี** label
- **C** regression ใช้ทำนาย **ตัวเลขต่อเนื่อง** ไม่ใช่ประเภท
- **D** ไม่มีการกระทำหรือรางวัลสะสม

### Q03 · ร้านต้องการแบ่งลูกค้าเป็นกลุ่มจากรูปแบบการซื้อ โดยยังไม่มีชื่อกลุ่มหรือคำตอบกำกับล่วงหน้า
> A. Regression เพื่อทำนายชื่อกลุ่มเป็นจำนวนเงินบาท B. Classification โดยใช้ชื่อกลุ่มที่ยังไม่มีเป็นคำตอบฝึก C. Reinforcement learning โดยให้รางวัลทุกครั้งที่อ่านข้อมูล D. Clustering ซึ่งเป็น unsupervised learning

**✅ คำตอบ: D**

**เหตุผล:** คำสำคัญคือ "**ยังไม่มีชื่อกลุ่มหรือคำตอบกำกับ**" = ไม่มี label → Unsupervised และเป้าหมายคือ "แบ่งเป็นกลุ่ม" → **Clustering** (เช่น K-Means) โดยอัลกอริทึมจะหาลูกค้าที่มีพฤติกรรมคล้ายกันเอง แล้วมนุษย์ค่อยตั้งชื่อกลุ่มภายหลัง

**ทำไมข้ออื่นผิด**
- **A** ชื่อกลุ่มไม่ใช่ปริมาณ และการแปลงเป็น "จำนวนเงินบาท" ไม่มีความหมาย
- **B** classification ต้องมี label สำหรับฝึก แต่โจทย์ยังไม่มี (ข้อนี้ขัดแย้งในตัวเอง)
- **C** การอ่านข้อมูลไม่ใช่ "การกระทำ" ที่มีผลต่อสภาพแวดล้อม จึงไม่ใช่ RL

### Q04 · หุ่นยนต์ในเกมจำลองเลือกเดินซ้าย/ขวา ได้รางวัลเมื่อถึงเป้าหมาย เป้าหมายคือรางวัลสะสมสูงขึ้น
> A. Supervised regression B. Unsupervised clustering C. Reinforcement learning D. การคำนวณค่าเฉลี่ยแบบไม่มีการเรียนรู้

**✅ คำตอบ: C**

**เหตุผล:** องค์ประกอบครบของ **Reinforcement Learning**
- **Agent** (หุ่นยนต์) ใน **Environment** (เกมจำลอง)
- **Action** (ซ้าย/ขวา)
- **Reward** (รางวัลเมื่อถึงเป้า)
- **เป้าหมาย** = เพิ่ม **รางวัลสะสม** ในระยะยาว (ไม่ใช่แค่รางวัลก้าวเดียว)

ไม่มีใครบอก "คำตอบที่ถูก" ของแต่ละก้าวล่วงหน้า หุ่นยนต์ต้องเรียนจากผลของการกระทำเอง

**ทำไมข้ออื่นผิด**
- **A** ไม่มีชุดข้อมูล (X, y) ที่ระบุคำตอบถูกของแต่ละก้าว
- **B** ไม่ได้จัดกลุ่มข้อมูล
- **D** มีการเรียนรู้เพื่อปรับพฤติกรรม ไม่ใช่แค่คำนวณสถิติ

### Q05 · ข้อมูลแต่ละแถวเป็นอิสระ ต้องเลือกความซับซ้อนของโมเดลและรายงานผลบนข้อมูลที่ไม่เคยใช้เลือกโมเดล
> A. ฝึกบน test แล้วใช้ train รายงานผล B. ฝึกบน train เลือกโมเดลด้วย validation และใช้ test ประเมินครั้งสุดท้าย C. รวมทุกชุดแล้วเลือกโมเดลที่มี training error ต่ำสุด D. เลือกโมเดลจาก test ซ้ำจนพอใจแล้วรายงานคะแนน test เดิม

**✅ คำตอบ: B**

**เหตุผล:** แต่ละชุดมีหน้าที่ต่างกัน
```
Train ──► เรียน coefficients     Validation ──► เลือก degree/alpha/features     Test ──► รายงานครั้งเดียว
```
โจทย์เน้นว่าผลสุดท้ายต้องอยู่บน "ข้อมูลที่ไม่เคยใช้เลือกโมเดล" ซึ่งก็คือ test ที่กันไว้ (และเพราะแถวเป็นอิสระ การแบ่งแบบสุ่มจึงใช้ได้)

**ทำไมข้ออื่นผิด**
- **A** สลับบทบาท และการรายงานบน train ประเมินเกินจริงเสมอ
- **C** training error ต่ำสุดมักได้โมเดลที่ซับซ้อนที่สุด (overfit) และไม่เหลือข้อมูลอิสระไว้ประเมิน
- **D** เมื่อใช้ test เลือกซ้ำ ๆ test จะกลายเป็น validation คะแนนที่รายงานจึง **ลำเอียงไปทางดี (optimistic)**

### Q06 · หลังแบ่ง train/validation/test ต้องเติมค่าว่างด้วยค่าเฉลี่ยและปรับสเกล ขั้นตอนใดลดการรั่วไหลของข้อมูล
> A. คำนวณค่าเฉลี่ยและสเกลจากข้อมูลทุกชุดก่อนฝึก B. คำนวณจาก test เท่านั้น C. คำนวณแยกในแต่ละชุดแล้วใช้สเกลคนละชุด D. เรียนรู้ค่าเฉลี่ยและสเกลจาก train แล้วใช้ค่าเดิมแปลง validation และ test

**✅ คำตอบ: D**

**เหตุผล:** ค่าเฉลี่ยที่ใช้เติมค่าว่าง และ mean/std ที่ใช้ปรับสเกล ถือเป็น **"พารามิเตอร์ที่เรียนจากข้อมูล"** เหมือน coefficient จึงต้องเรียนจาก train เท่านั้น แล้ว **ใช้ค่าเดิม** แปลงชุดอื่น เพื่อจำลองสถานการณ์จริงที่ตอนพยากรณ์ยังไม่เห็นข้อมูลอนาคต

```python
imp = SimpleImputer(strategy="mean").fit(X_train)   # เรียนจาก train
sc  = StandardScaler().fit(imp.transform(X_train))
X_val_ready = sc.transform(imp.transform(X_val))     # ใช้ค่าเดิม แค่ transform
# ง่ายกว่า: make_pipeline(SimpleImputer(), StandardScaler(), model).fit(X_train, y_train)
```

**ทำไมข้ออื่นผิด**
- **A** ข้อมูล validation/test ไหลเข้าไปในค่าเฉลี่ยและสเกล → **leakage**
- **B** ใช้ test ตรง ๆ ยิ่งรั่วหนัก
- **C** แต่ละชุดถูกแปลงคนละมาตรฐาน ค่า 0 ใน train กับค่า 0 ใน test จึงไม่ได้หมายถึงระดับเดียวกัน โมเดลจะเห็นข้อมูลที่ถูกเลื่อนหรือยืดไป (และตอนใช้งานจริงแถวเดียวก็คำนวณสเกลเองไม่ได้)

### Q07 · baseline RMSE = 12, เส้นตรง train RMSE = 11 / validation = 12, โมเดลยืดหยุ่นกว่าลดทั้งสองค่าได้มาก
> A. เส้นตรงอาจ underfit เพราะความซับซ้อนไม่พอ B. เส้นตรง overfit แน่นอนเพราะ train error สูง C. Validation error ต้องเป็นศูนย์จึงจะวินิจฉัยได้ D. ข้อมูลพิสูจน์ว่าไม่มี noise

**✅ คำตอบ: A**

**เหตุผล:** อ่านสัญญาณ 3 อย่าง
1. เส้นตรง **train error สูง** (11) ใกล้ baseline (12) → แทบเรียนอะไรไม่ได้
2. train กับ validation **ใกล้กัน** (11 vs 12) → ไม่ใช่อาการ overfit
3. โมเดลยืดหยุ่นกว่า **ลดได้ทั้งคู่** → แสดงว่ายังมีรูปแบบที่เส้นตรงจับไม่ได้

ทั้งหมดนี้ชี้ว่า **underfit (bias สูง)** คำว่า "อาจ" เหมาะสม เพราะเป็นหลักฐานจากการแบ่งข้อมูลครั้งเดียว

**ทำไมข้ออื่นผิด**
- **B** overfit คือ train **ต่ำ** แต่ validation **สูงกว่ามาก** ซึ่งตรงข้ามกับที่เห็น และคำว่า "แน่นอน" เกินหลักฐาน
- **C** ไม่ต้องมี error เป็นศูนย์ก็วินิจฉัยได้ (ข้อมูลจริงมี noise เสมอ)
- **D** ไม่มีข้อมูลใดพิสูจน์ว่าไม่มี noise

### Q08 · ฝึกโมเดลชนิดเดิมด้วยชุดฝึกหลายชุดจากประชากรเดียวกัน แล้วค่าทำนายที่ x เดิมเปลี่ยนมาก
> A. Bias ต่ำเสมอ B. Residual ทุกค่าต้องเป็นศูนย์ C. Variance สูง D. R² เท่ากับ 1 เสมอ

**✅ คำตอบ: C**

**เหตุผล:** นี่คือ **นิยามของ variance โดยตรง** = ค่าทำนาย ณ จุดเดิมผันผวนมากแค่ไหนเมื่อเปลี่ยนชุดฝึก (ความไวต่อข้อมูลฝึก) มักพบในโมเดลซับซ้อน เช่น polynomial degree สูง หรือ decision tree ลึก

**ทำไมข้ออื่นผิด**
- **A** variance สูงไม่ได้บอกอะไรแน่นอนเกี่ยวกับ bias (มักมาคู่กับ bias ต่ำ แต่ไม่ใช่ "เสมอ")
- **B** residual เป็นศูนย์ทุกค่าไม่เกี่ยวกับความผันผวนระหว่างชุดฝึก
- **D** R² = 1 หมายถึงทำนายสมบูรณ์ ซึ่งไม่เกี่ยวข้องกับปรากฏการณ์นี้

### Q21 · เปรียบเทียบ Ridge โดย feature หนึ่งหน่วยบาท อีกตัวหน่วยกิโลเมตร

**ทำไมต้องใช้ Pipeline:** เพื่อให้ scaler ถูก fit ใหม่จาก **ชุดฝึกของแต่ละรอบ** เท่านั้น (สำคัญมากตอนทำ cross-validation ไม่อย่างนั้น fold ที่ใช้ประเมินจะรั่วเข้าไปในสเกล)

- **C** leakage

### Q26 · ต้องการให้ Linear Regression แทนผลของวันจันทร์–อาทิตย์แยกกัน โดยไม่บังคับให้ผลเพิ่มเท่ากันจากเลขวัน 1 ไป 7

### Q30 · n = 50 แถว, SSE = Σ(y − ŷ)², MSE = SSE/50 ไม่มี regularization พารามิเตอร์ที่ลด SSE กับที่ลด MSE สัมพันธ์กันอย่างไร

### Q31 · รันโค้ดซ้ำโดยเริ่ม `rng = np.random.default_rng(42)` ทุกครั้ง และใช้ rng นี้สร้าง x และ noise ใน y = 2x + 1 + noise
> A. ข้อมูลเหมือนเดิม และ sample correlation ต้องเท่ากับ 1 เสมอ B. ข้อมูลเปลี่ยนทุกครั้ง C. seed ทำให้ noise ทุกแถวเป็นศูนย์ D. ข้อมูลเหมือนเดิมเมื่อเรียกสุ่มตามลำดับเดิม แต่ seed ไม่ได้บังคับว่า correlation ต้องเท่ากับ 1

- **A** ครึ่งแรกถูก แต่ correlation = 1 ต้องไม่มี noise
- **B** ขัดกับหน้าที่ของ seed
- **C** seed ไม่ได้กำหนดขนาดของ noise (ขนาดกำหนดด้วย `scale` ของการแจกแจง)

### Q32 · `PolynomialFeatures(degree=3, include_bias=False)` กับ feature x ตัวเดียว เมื่อ x = 2
> A. [1, 2, 3] และเป็นเส้นตรงใน x เท่านั้น B. [2, 4, 8] และยังเป็นเชิงเส้นในสัมประสิทธิ์ แม้กราฟเทียบ x อาจโค้ง C. [2, 6, 18] และไม่สามารถมี intercept D. [1, 2, 4, 8] และ include_bias=False หมายถึงลบ noise ออก

**✅ คำตอบ: B**

**วิธีคิด:** degree 3 สร้าง [x, x², x³] = [2, 2², 2³] = **[2, 4, 8]**
- `include_bias=False` = **ไม่เพิ่มคอลัมน์ค่าคงที่ 1** (เพราะ LinearRegression มี intercept ของตัวเองอยู่แล้ว ใส่ซ้ำจะซ้ำซ้อน)
- โมเดล ŷ = b₀ + b₁x + b₂x² + b₃x³ เป็นผลรวมเชิงเส้นของ coefficient → **linear in parameters** จึงยังใช้ OLS ได้ แต่กราฟ ŷ เทียบ x เป็นเส้นโค้ง

**ทำไมข้ออื่นผิด**
- **A** [1, 2, 3] ไม่ใช่การยกกำลัง และโมเดลโค้งได้
- **C** [2, 6, 18] ไม่ใช่ x^k และโมเดลยังมี intercept ได้ (จาก LinearRegression)
- **D** [1, 2, 4, 8] คือกรณี `include_bias=True` และ bias ในที่นี้คือคอลัมน์ค่าคงที่ ไม่ใช่ noise

### Q33 · centers = linspace(train_min, train_max, N), σ = width_factor × ระยะห่างของ centers; train_min 0, train_max 10, N = 6, width_factor 0.5
> A. 0.5 B. 5 C. 1 (centers ห่างกัน 2) D. 6

**✅ คำตอบ: C (σ = 1 หน่วยของ x)**

**วิธีคิด:**
1. `linspace(0, 10, 6)` = [0, 2, 4, 6, 8, 10] → มี 6 จุด 5 ช่วง → ระยะห่าง = (10 − 0)/(6 − 1) = **2**

**ทำไมข้ออื่นผิด**
- **A** ใช้ factor เป็น σ ตรง ๆ (ผิดตามนิยามที่โจทย์ให้)
- **B** คูณ factor กับ train_max
- **D** เป็นจำนวน centers ไม่ใช่ความกว้าง

### Q34 · เปรียบเทียบ OLS, Ridge, Lasso บน Gaussian basis ชุดเดียวกัน การทดลองใดแยกผลของ penalty ได้ดีที่สุด
> A. ใช้ train/validation/test เดียวกัน ใช้ centers ความกว้าง และการปรับสเกลที่ fit จาก train เดียวกัน แล้วเปรียบเทียบ validation โดยเก็บ test ไว้ตอนสุดท้าย B. OLS 5 basis, Ridge 10, Lasso 30 แล้วสรุปว่าความต่างทั้งหมดเกิดจาก penalty C. ให้แต่ละโมเดลเลือก features จาก test ก่อน แล้วใช้ training error ตัดสิน D. ใช้ alpha ตัวเลขเดียวกันแล้วถือว่า Ridge กับ Lasso มี penalty แรงเท่ากัน

**✅ คำตอบ: A**

**เหตุผล:** หลักการทดลองแบบควบคุม — **เปลี่ยนสิ่งเดียว (ชนิด penalty) คงสิ่งอื่นทั้งหมด** ได้แก่ การแบ่งข้อมูล, centers, σ, scaler (fit จาก train) แล้วเทียบบน validation และเก็บ test ไว้ครั้งสุดท้าย ผลต่างที่เห็นจึงโยงไปที่ penalty ได้

**ทำไมข้ออื่นผิด**
- **B** เปลี่ยนจำนวน basis พร้อม penalty → ผลต่างอาจมาจากความยืดหยุ่นของ basis ไม่ใช่ penalty (**confounding**)
- **C** ใช้ test เลือก (leakage) และตัดสินด้วย training error (ส่งเสริม overfit)
- **D** alpha เลขเดียวกันไม่ได้แปลว่าแรงเท่ากัน เพราะ L1 (Σ|β|) กับ L2 (Σβ²) มีสเกลต่างกัน และ scikit-learn ยังนิยาม loss ต่างกัน: Ridge ใช้ ‖y − Xβ‖² + α‖β‖² ส่วน Lasso ใช้ (1/(2n))‖y − Xβ‖² + α‖β‖₁ → ต้องจูน alpha แยกกันในแต่ละวิธี

### P01 · ฝึกและประเมินโมเดลจริง (6 คะแนน)

```python
dev = pd.read_csv("regression_development.csv", parse_dates=["date"]).sort_values("date").reset_index(drop=True)

feature_sets = {"Simple":   ["temp_forecast_c"],

results, models = {}, {}
for name, feats in feature_sets.items():
    m = LinearRegression().fit(train[feats], train[target])   # fit เฉพาะ train

    models[name] = m
    print(name, "intercept =", round(m.intercept_, 3), "coef =", dict(zip(feats, m.coef_.round(3))))

print(pd.DataFrame(results).T.round(3))
best = min(results, key=lambda k: results[k]["RMSE"])
print("เลือก:", best)
```

### P02 · ทดลอง Bias–Variance (4 คะแนน) — ✅ รันจริง

**Protocol:** y = sin(x) + noise (σ = 0.25), x ~ Uniform(0, 6), train 35 จุด (seed 11, 22, 33), validation 200 จุด (seed 2026 คงที่), degree 1, 3, 12, รายงาน train/validation RMSE และค่าทำนายที่ x = 2.0

```python
def make(seed, n):
    rng = np.random.default_rng(seed)
    x = rng.uniform(0, 6, n)                      # สร้าง x ก่อน
    y = np.sin(x) + rng.normal(0, 0.25, n)        # แล้วค่อยสร้าง noise
    return x.reshape(-1, 1), y

X_val, y_val = make(2026, 200)                    # validation คงที่ทุกรอบ
rmse = lambda a, b: np.sqrt(np.mean((a - b) ** 2))
rows = []
for seed in [11, 22, 33]:
    X_tr, y_tr = make(seed, 35)
    for d in [1, 3, 12]:
        m = make_pipeline(PolynomialFeatures(d, include_bias=False),
                          StandardScaler(), LinearRegression()).fit(X_tr, y_tr)
        rows.append([seed, d, rmse(y_tr, m.predict(X_tr)),
                     rmse(y_val, m.predict(X_val)), m.predict([[2.0]])[0]])
print(pd.DataFrame(rows, columns=["seed","degree","train_RMSE","val_RMSE","pred_x2"]).round(4))
```
> ใส่ `StandardScaler` คั่นเพื่อความเสถียรเชิงตัวเลขของ degree 12 (x¹² มีค่าถึง ~2 พันล้าน) สำหรับ OLS ที่ไม่มี penalty การ scale ไม่เปลี่ยนคำทำนายในทางทฤษฎี

**ผลที่ได้** (ค่าจริง sin(2.0) = **0.9093**)

**สรุปผลและตีความ**

1. **Degree 1 — หลักฐาน underfit (bias สูง):** train RMSE สูง (0.36–0.48) ใกล้กับ validation (≈0.48) ทุกรอบ ทั้งที่ระดับ noise คือ 0.25 → เส้นตรงจับรูปคลื่น sin ไม่ได้ ค่าทำนายที่ x = 2 อยู่ที่ 0.36–0.45 **ต่ำกว่าค่าจริง 0.91 อย่างเป็นระบบทุกรอบ** (ผิดทางเดียวกันเสมอ = bias)
2. **Degree 3 — เหมาะสมที่สุด:** validation RMSE ต่ำสุดทุกรอบ (0.25–0.28 ใกล้ระดับ noise 0.25 ซึ่งเป็นขอบล่างที่คาดได้) ค่าทำนายที่ x = 2 อยู่ที่ 0.81–0.98 ล้อมรอบค่าจริง
3. **Degree 12 — หลักฐาน overfit (variance สูง):** train RMSE ต่ำสุดทุกรอบ (0.16–0.20 ต่ำกว่าระดับ noise = เริ่มจำ noise) แต่ validation แย่กว่า degree 3 ทุกรอบ และ **ผันผวนมาก** (0.37 → 2.96 → 0.67) รอบ seed 22 ระเบิดถึง 2.96 เพราะเส้นแกว่งแรงบริเวณขอบช่วง x ที่มีจุดฝึกน้อย
4. **ความไวของค่าทำนายที่ x = 2.0 ต่อการเปลี่ยนชุดฝึก**

   | degree | ช่วงค่าทำนาย 3 รอบ | กว้าง | ตีความ |
   |---|---|---|---|
   | 1 | 0.36 – 0.45 | 0.08 | ไวน้อย แต่ผิดเป้าอย่างเป็นระบบ |
   | 3 | 0.81 – 0.98 | 0.17 | ไวปานกลาง อยู่รอบค่าจริง |
   | 12 | 0.90 – 1.37 | 0.47 | ไวมากที่สุด |

   ที่ x = 2 (กลางช่วงข้อมูล) degree 12 ยังไม่เลวร้ายนัก ความเสียหายหลักเกิดที่ **ขอบช่วง** ซึ่งสะท้อนใน validation RMSE รอบ seed 22

5. **ข้อจำกัดของการใช้เพียง 3 รอบ**
   - 3 รอบน้อยเกินไปที่จะประมาณ bias² และ variance ได้แม่น (ช่วงค่าทำนายจาก 3 ค่าเป็นค่าประมาณหยาบมาก)
   - ผลของ degree 12 ขึ้นกับว่าแต่ละรอบสุ่มได้จุดใกล้ขอบหรือไม่ รอบเดียว (seed 22) ก็ดึงภาพรวมได้มาก
   - ดูค่าทำนายที่จุดเดียว (x = 2) ไม่ได้แทนพฤติกรรมทั่วทั้งช่วง
   - ควรเพิ่มเป็นหลายสิบ–ร้อยรอบ แล้วคำนวณ bias² = (ค่าเฉลี่ยคำทำนาย − sin(2))² และ variance = ความแปรปรวนของคำทำนาย ถ้าต้องการตัวเลขที่เชื่อถือได้
   - ผลครั้งนี้ **บังเอิญสอดคล้องกับทฤษฎี** แต่ในการทดลองจริงอาจมีรอบที่ degree 12 ดีกว่า degree 3 ได้ จึงไม่ควรสรุปจากรอบเดียว

| บวกหรือลบติดกันเป็นช่วงตามวันที่ | autocorrelation / แนวโน้มตามเวลาที่ยังไม่ได้ใส่ | feature ตามเวลา (ระวังใช้เฉพาะที่รู้ล่วงหน้า) |
| สองกลุ่มสีแยกกัน | ผลของ working_day อาจต่างตามอุณหภูมิ | interaction temp × working_day (ถ้ามีเหตุผล) |

**ข้อจำกัดของการอ่านกราฟ (ต้องเขียน):** มีเพียง **18 จุด** รูปแบบที่เห็นอาจเกิดจากความบังเอิญ, validation เป็นช่วงเวลาเดียวต่อเนื่อง (อาจเป็นฤดูเดียว) จึงไม่เป็นตัวแทนทั้งปี, กราฟช่วย "ตั้งข้อสงสัย" ไม่ใช่ "พิสูจน์" สมมติฐาน

**ขั้นที่ 2: เปรียบเทียบ candidate A–D**

```python
dev["temp2"] = dev["temp_forecast_c"] ** 2          # สร้างก่อนแบ่ง ใช้ได้ เพราะคำนวณรายแถว ไม่ได้เรียนค่าจากข้อมูล
train, val = dev.iloc[:72], dev.iloc[72:]
fA = ["temp_forecast_c", "working_day"]
fB = ["temp_forecast_c", "temp2", "working_day"]
cands = {   # (ชื่อ, features, pipeline, ลำดับความง่าย)
  "A": (fA, LinearRegression(), 0),
  "B": (fB, LinearRegression(), 1),
  "C": (fB, make_pipeline(StandardScaler(), Ridge(alpha=0.1)), 2),
  "D": (fB, make_pipeline(StandardScaler(), Ridge(alpha=10)), 3),
}
val_rmse = {}
for k, (f, est, _) in cands.items():
    est.fit(train[f], train[target])                              # ทุกขั้นตอน fit บน train เดิม
    val_rmse[k] = np.sqrt(mean_squared_error(val[target], est.predict(val[f])))
print({k: round(v, 4) for k, v in val_rmse.items()})

# กฎการเลือก: RMSE ต่ำสุด แต่ถ้าต่างจากตัวที่ต่ำสุด < 0.01 kWh ให้เลือกตัวที่ง่ายกว่า
best_val = min(val_rmse.values())
tied = [k for k in val_rmse if val_rmse[k] - best_val < 0.01]
chosen = min(tied, key=lambda k: cands[k][2])        # ลำดับ A < B < C < D (C ก่อน D = alpha ต่ำกว่า)
print("เลือก:", chosen)
```
> ลำดับความง่ายที่ใช้: A (2 features, ไม่มี penalty) → B (เพิ่ม temp²) → C, D (โครงสร้างเท่ากัน ใช้กฎ "alpha ต่ำกว่า" → C ก่อน D) ให้ระบุการตีความลำดับนี้ในคำตอบด้วย

**อธิบาย trade-off (ต้องมีในคำตอบ)**
- **เพิ่ม temp²** ลด bias ได้ถ้าความสัมพันธ์โค้งจริง แต่เพิ่ม variance (ประมาณพารามิเตอร์มากขึ้นจาก 72 แถว) และมักทำให้ extrapolate แย่ลงนอกช่วงอุณหภูมิที่เห็น ถ้าความสัมพันธ์ในช่วงข้อมูลเกือบเป็นเส้นตรง B จะไม่ดีขึ้น
- **Ridge alpha 0.1** แทบไม่ต่างจาก B เพราะ penalty เบา
- **Ridge alpha 10** หด coefficient มาก → variance ลด แต่ bias เพิ่ม ถ้าโมเดลไม่ได้ overfit อยู่แล้ว (มีแค่ 3 features กับ 72 แถว) penalty แรงอาจทำให้ **แย่ลง**
- ⇒ "เพิ่ม feature หรือ penalty แล้วไม่จำเป็นต้องดีขึ้น" เพราะแต่ละอย่างแก้ปัญหาคนละด้าน (bias หรือ variance) ถ้าไม่ตรงกับปัญหาที่มีอยู่จริงก็ไม่ช่วย

**ขั้นที่ 3: refit บน development 90 แถว แล้วประเมิน final test ครั้งเดียว**

```python
f, est, _ = cands[chosen]
est.fit(dev[f], dev[target])                         # refit บน dev ทั้ง 90 แถว (โครงสร้างเดิม ไม่เลือกใหม่)
test = pd.read_csv("regression_final_test.csv", parse_dates=["date"]).sort_values("date")
test["temp2"] = test["temp_forecast_c"] ** 2
print(report(test[target], est.predict(test[f])))    # รายงานครั้งเดียว ห้ามย้อนไปเปลี่ยน candidate
```

**สิ่งที่ต้องส่ง:** กราฟ residual 2 รูป, ตาราง validation RMSE ของ A–D, เหตุผลการเลือกตามกฎ, ผล final test (MAE, RMSE, R² พร้อมหน่วย), ข้อสรุปว่าผล test สอดคล้องกับ validation หรือไม่ (ถ้าต่างมาก ให้รายงานตามจริงพร้อมคาดเดาสาเหตุ เช่น ฤดูกาลเปลี่ยน — **ห้ามเลือกโมเดลใหม่จากผล test**)

### P04 · ข้อมูลตามเวลาและ Bootstrap (4 คะแนน)

**ขั้นที่ 1: ตีความ coefficient ของ temp_forecast_c ใน model A**
- **หน่วย:** kWh ต่อ °C (target หน่วย kWh หารด้วย feature หน่วย °C)
- **ความหมาย:** "เมื่อ working_day คงเดิม อุณหภูมิพยากรณ์ที่สูงขึ้น 1 °C สัมพันธ์กับค่าการใช้ไฟที่โมเดลทำนายเปลี่ยนไป β kWh"
- **ไม่สรุปเป็นเหตุและผล** เพราะเป็นข้อมูลสังเกต อาจมีปัจจัยร่วม เช่น ฤดูกาล วันหยุดยาว หรือช่วงปิดภาคเรียน ที่เปลี่ยนพร้อมอุณหภูมิ

**ขั้นที่ 2: Bootstrap ทั้งสองแบบ**

```python
X = dev[fA].to_numpy(); y = dev[target].to_numpy(); n = len(dev)   # 90 วัน เรียงตามวันที่
coef_temp = lambda idx: LinearRegression().fit(X[idx], y[idx]).coef_[0]
B = 300

# (1) Ordinary pairs bootstrap: สุ่มแถว (X, y) พร้อมใส่คืน
rng = np.random.default_rng(20260922)
ord_coefs = [coef_temp(rng.integers(0, n, n)) for _ in range(B)]

# (2) Moving-block pairs bootstrap: บล็อก 7 วันติดกัน
rng = np.random.default_rng(20260922)          # seed เดียวกัน เริ่ม generator ใหม่สำหรับวิธีนี้
L = 7; starts = np.arange(n - L + 1)           # จุดเริ่มบล็อกที่เป็นไปได้: 0..83 (บล็อกไม่ล้นข้อมูล)
blk_coefs = []
for _ in range(B):
    idx = []
    while len(idx) < n:                        # ต่อบล็อกจนได้อย่างน้อย 90 แถว
        s = rng.choice(starts); idx.extend(range(s, s + L))
    blk_coefs.append(coef_temp(np.array(idx[:n])))   # ตัดเหลือ 90 แถว

for name, c in [("ordinary", ord_coefs), ("moving-block", blk_coefs)]:
    lo, hi = np.percentile(c, [2.5, 97.5])
    print(f"{name:13s} 2.5% = {lo:.4f}  97.5% = {hi:.4f}  width = {hi-lo:.4f}")
```

**สิ่งที่ต้องเขียน**

| วิธี | สมมติฐานเรื่องการพึ่งพากัน | สิ่งที่มักเห็น |
|---|---|---|
| Ordinary pairs | แต่ละวัน **เป็นอิสระ** และมาจากการแจกแจงเดียวกัน (i.i.d.) | ถ้า error สัมพันธ์ตามเวลาจริง ช่วงมักแคบเกินจริง |
| Moving-block (7 วัน) | ความพึ่งพามีอยู่ **ภายในช่วงสั้น ๆ** (≤ ~7 วัน) และบล็อกที่ห่างกันพอเป็นอิสระโดยประมาณ | มักได้ช่วงกว้างกว่า ถ้ามี autocorrelation (แต่ไม่รับประกันเสมอ) |

- รายงาน percentile 2.5 และ 97.5 ของทั้งสองวิธี และเทียบความกว้าง (ถ้าผลออกมาใกล้กัน ก็รายงานตามจริง: แปลว่า autocorrelation อาจไม่แรงในข้อมูลนี้)
- ⚠️ บล็อก 7 วันเป็นค่ากำหนดเพื่อการฝึก **ไม่อ้างว่าเหมาะที่สุดหรือรับประกัน coverage 95%**

**ทำไมช่วงที่ได้ไม่ใช่ "ช่วงทำนาย" (prediction interval) ของการใช้ไฟวันใหม่**
- ช่วงนี้วัดความไม่แน่นอนของ **พารามิเตอร์ β** (ถ้าเก็บข้อมูลใหม่ β จะแกว่งแค่ไหน)
- การใช้ไฟของวันใหม่มีความไม่แน่นอนเพิ่มจาก **noise ของวันนั้น** (ตัว ε) และความไม่แน่นอนของพารามิเตอร์ตัวอื่น (intercept, coef ของ working_day) ด้วย ช่วงทำนายจึง **กว้างกว่ามาก** และมีหน่วยเป็น kWh ไม่ใช่ kWh/°C

**ตัวอย่าง feature วันในสัปดาห์ที่รู้ได้ ณ เวลาพยากรณ์:** one-hot ของ **วันในสัปดาห์ของวันเป้าหมาย** (จันทร์–อาทิตย์, ตัดหนึ่งวันเป็นวันอ้างอิงเมื่อมี intercept) หรือ `is_weekend` / `is_public_holiday` ของวันพรุ่งนี้ ซึ่งรู้ได้จากปฏิทินล่วงหน้า

### P05 · Gaussian basis และการเปรียบเทียบ penalty (4 คะแนน) — ✅ รันจริง

**Protocol:** y = sin(x) + ε, x ~ U(0, 10), ε ~ N(0, 0.15²); train 50 จุด (seed 41), validation 100 (seed 42), final test 100 (seed 43) แต่ละชุดมี generator ของตัวเอง

```python
def make(seed, n):
    rng = np.random.default_rng(seed)
    x = rng.uniform(0, 10, n); y = np.sin(x) + rng.normal(0, 0.15, n)
    return x, y
x_tr, y_tr = make(41, 50); x_va, y_va = make(42, 100); x_te, y_te = make(43, 100)

# (1) Polynomial features ของ 3 จุดแรก
print(PolynomialFeatures(3, include_bias=False).fit_transform(x_tr[:3].reshape(-1, 1)))

# Gaussian basis: centers และ σ มาจาก train เท่านั้น
N, wf = 12, 0.8
centers = np.linspace(x_tr.min(), x_tr.max(), N)
sigma = wf * (centers[1] - centers[0])
phi = lambda x: np.exp(-0.5 * ((x[:, None] - centers[None, :]) / sigma) ** 2)
F_tr, F_va, F_te = phi(x_tr), phi(x_va), phi(x_te)

# (2) StandardScaler fit จาก train, ใช้ชุดเดียวกันกับทุกโมเดล
sc = StandardScaler().fit(F_tr)
F_tr, F_va, F_te = sc.transform(F_tr), sc.transform(F_va), sc.transform(F_te)
models = {"OLS": LinearRegression(), "Ridge": Ridge(alpha=0.1),
          "Lasso": Lasso(alpha=0.001, max_iter=100000, tol=1e-6)}
rmse = lambda a, b: np.sqrt(np.mean((a - b) ** 2))
val = {}
for k, m in models.items():
    m.fit(F_tr, y_tr); val[k] = rmse(y_va, m.predict(F_va))
    print(k, rmse(y_tr, m.predict(F_tr)), val[k])

# (3) เลือกตาม validation; เสมอกัน (≤1e-6) ใช้ลำดับ OLS, Ridge, Lasso
order = ["OLS", "Ridge", "Lasso"]; best = min(val.values())
chosen = next(k for k in order if val[k] - best <= 1e-6)
print("เลือก", chosen, "final-test RMSE =", rmse(y_te, models[chosen].predict(F_te)))
```

**ผลข้อ 1: Polynomial features ของ train 3 จุดแรก**

| x | x² | x³ |
|---|---|---|
| 9.5415 | 91.0404 | 868.6633 |
| 7.6793 | 58.9720 | 452.8647 |
| 1.2597 | 1.5869 | 1.9990 |

(สังเกตสเกลของ x³ ต่างจาก x หลายร้อยเท่า → ถ้าจะใช้ penalty ต้อง scale ก่อน)

**ผลข้อ 1: Gaussian basis**
- train_min = 0.5848, train_max = 9.9429
- centers (12 จุด) = [0.5848, 1.4356, 2.2863, 3.1370, 3.9878, 4.8385, 5.6893, 6.5400, 7.3907, 8.2415, 9.0922, 9.9429]
- ระยะห่าง = (9.9429 − 0.5848)/11 = **0.8507** → σ = 0.8 × 0.8507 = **0.6806**
- ขนาด feature matrix: train **(50, 12)**, validation (100, 12), test (100, 12)

**ผลข้อ 2: เปรียบเทียบ 3 โมเดล (basis และสเกลชุดเดียวกัน)**

| โมเดล | train RMSE | validation RMSE | max \|coef\| | ‖coef‖₂ | coef = 0 |
|---|---|---|---|---|---|
| **OLS** | 0.1240 | **0.1775** | 0.389 | 0.773 | 0 |
| Ridge (α = 0.1) | 0.1246 | 0.1807 | 0.261 | 0.479 | 0 |
| Lasso (α = 0.001) | 0.1246 | 0.1778 | 0.268 | 0.495 | 1 |

**ผลข้อ 3:** validation RMSE ต่ำสุดคือ **OLS (0.1775)** (Lasso 0.1778 ต่างกัน 0.0003 ซึ่งมากกว่า 1e-6 จึงไม่นับว่าเสมอ) → ใช้โมเดล OLS ที่ฝึกบน train เดิม
→ **final-test RMSE = 0.1772** (รายงานครั้งเดียว ไม่ refit ไม่เลือกใหม่)

**ผลข้อ 4: อธิบายจากผลจริง**

1. **penalty เปลี่ยนผลอย่างไร**
   - Coefficient **หดชัดเจน**: ‖coef‖₂ ลดจาก 0.77 (OLS) เหลือ 0.48 (Ridge) และ 0.50 (Lasso), ค่าสูงสุดลดจาก 0.39 เหลือ ~0.26–0.27
   - Lasso ทำให้ coefficient **1 ตัวเป็นศูนย์พอดี** ส่วน Ridge ไม่มีตัวใดเป็นศูนย์ — ตรงตามทฤษฎี L1 vs L2
   - แต่ **error แทบไม่เปลี่ยน** (train เพิ่มเพียง 0.0006, validation ต่างกันไม่ถึง 0.004) เพราะ OLS ที่มี 12 basis กับ 50 จุด **ไม่ได้ overfit มาก** อยู่แล้ว (train 0.124 ต่ำกว่า noise 0.15 เล็กน้อย, validation 0.178) penalty จึงไม่มีอะไรให้แก้มาก และ Ridge ยังแย่ลงเล็กน้อยเพราะเพิ่ม bias
   - บทเรียน: penalty ช่วยเมื่อโมเดลมี variance สูง (เช่น N ใหญ่หรือ σ แคบ) ไม่ใช่ช่วยเสมอ
   - หมายเหตุ: validation และ test มี x ต่ำกว่า train_min (ต่ำสุด 0.07 และ 0.04 ขณะ train_min = 0.58) จุดเหล่านั้นอยู่นอกช่วง centers เล็กน้อย จึงเป็น extrapolation เล็กน้อยที่ basis รองรับได้ไม่ดีนัก

2. **ทำไม alpha เลขเดียวกันข้าม Ridge/Lasso ไม่รับประกันแรง penalty เท่ากัน**
   - L2 ลงโทษ Σβ² ส่วน L1 ลงโทษ Σ|β| หน่วยและสเกลต่างกัน: ถ้า β = 0.1 จะได้ β² = 0.01 แต่ |β| = 0.1 (ต่างกัน 10 เท่า)
   - scikit-learn นิยาม loss ต่างกัน: Ridge = ‖y − Xβ‖² + α‖β‖² (ไม่หารด้วย n) ส่วน Lasso = (1/2n)‖y − Xβ‖² + α‖β‖₁ (หารด้วย 2n)
   - ในผลจริง Ridge α = 0.1 กับ Lasso α = 0.001 (ต่างกัน 100 เท่า) กลับหด ‖coef‖₂ ได้ **ใกล้เคียงกัน** (0.48 vs 0.50) → ตัวเลข alpha เทียบข้ามวิธีตรง ๆ ไม่ได้ ต้องจูนแยกแต่ละวิธีด้วย validation

3. **ทำไมเปลี่ยน N พร้อมชนิด penalty จึงแยกสาเหตุได้ยาก**
   - N ควบคุม **ความยืดหยุ่นของโมเดล** (และเพราะ σ = factor × spacing การเปลี่ยน N ยังเปลี่ยน σ ด้วย) ส่วน penalty ควบคุม **ขนาด coefficient**
   - ถ้าเปลี่ยนทั้งสองพร้อมกันแล้วผลต่าง จะไม่รู้ว่ามาจาก basis ที่ยืดหยุ่นขึ้น/ลดลง หรือจาก penalty = ตัวแปรกวน (confounding)
   - วิธีที่ถูก: คง N, centers, σ, scaler และการแบ่งข้อมูล แล้วเปลี่ยนเฉพาะ penalty (อย่างที่ทำในการทดลองนี้) หรือทำ grid ที่ครบทุกคู่ (N × penalty) แล้ววิเคราะห์ทีละมิติ

**กราฟที่ควรแนบ:** (ก) เส้น basis ทั้ง 12 ตัวเทียบ x (ข) จุด train/validation กับเส้นทำนายของ 3 โมเดลและเส้น sin(x) จริง

```python
xs = np.linspace(0, 10, 400); Fs = sc.transform(phi(xs))
plt.scatter(x_tr, y_tr, s=12, label="train"); plt.plot(xs, np.sin(xs), "k--", label="sin(x)")
for k, m in models.items(): plt.plot(xs, m.predict(Fs), label=k)
plt.legend(); plt.xlabel("x"); plt.ylabel("y"); plt.show()
```
