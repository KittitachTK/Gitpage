## 2. ประเภทของ Machine Learning (บท 07 LO1–LO2)

**Machine Learning** เป็นส่วนหนึ่งของ AI ที่ **เรียนรู้รูปแบบจากข้อมูล**
⚠️ ข้อมูลมากขึ้นไม่ได้รับประกันว่าโมเดลจะดีขึ้น ถ้าข้อมูลผิดหรือไม่ตรงกับงาน

| วิธี | ข้อมูลที่ใช้เรียนรู้ | ตัวอย่างงาน |
|---|---|---|
| **Supervised** (มีคำตอบเป้าหมาย) | X = ข้อมูลนำเข้า, y = คำตอบในอดีต | ทำนายเวลาส่งพัสดุจากประวัติที่มีเวลาส่งจริง |
| **Unsupervised** (ค้นหาโครงสร้าง) | ไม่มี label เป้าหมาย | แบ่งกลุ่มรูปแบบการซื้อ เพื่อสำรวจลักษณะลูกค้า |
| **Reinforcement** (เรียนจากผลการกระทำ) | สถานะ, การกระทำ, รางวัลสะสมตามเวลา | ฝึกตัวแทนจัดเส้นทางในระบบจำลองจากรางวัลและต้นทุน |

### Regression vs Classification — ต่างกันที่ "เป้าหมาย" ไม่ใช่ที่ข้อมูลนำเข้า

- "ส่งถึงใน **กี่นาที**?" → **Regression** (ต้องการปริมาณตัวเลข)
- "จะส่ง **ทันหรือไม่**?" → **Classification** (ต้องการประเภท)
- ใช้ X ชุดเดียวกันก็เป็นคนละงานได้

**กับดักที่พบบ่อย**
- ตัวเลขที่เป็น **รหัส** (ประเภทสินค้า 1, 2, 3) → ไม่ทำให้งานเป็น Regression เพราะตัวเลขไม่ได้แทนปริมาณ
- **จำนวน** สินค้า (จำนวนเต็ม) → เป็นปริมาณ ใช้ Regression หรือโมเดลข้อมูลนับได้ แต่ต้องตรวจว่าค่าพยากรณ์เหมาะกับงาน (เช่น ไม่ติดลบ)

### กฎที่แน่นอนอาจไม่ต้องใช้ ML
- ค่าส่งคำนวณจากสูตรน้ำหนัก × ระยะทางที่แน่นอน → **เขียนกฎตรง ๆ** ไม่ต้องใช้ ML
- เวลาส่งที่ขึ้นกับจราจร สภาพอากาศ ความไม่แน่นอน → ML ช่วยเรียนรู้จากประวัติได้

## 3. Workflow และการแบ่งข้อมูล (บท 07 LO3)

**ก่อนฝึกโมเดล** ให้กำหนดเป้าหมาย หน่วยของความผิดพลาด และ **เวลาที่ข้อมูลแต่ละตัวพร้อมใช้งาน**

ตัวอย่าง: พยากรณ์ยอดสั่งอาหารของวันพรุ่งนี้เพื่อวางแผนวัตถุดิบ

| ขั้น | สิ่งที่ทำ |
|---|---|
| 1. กำหนดปัญหา | พยากรณ์ยอดพรุ่งนี้ → ใช้วางแผนวัตถุดิบ |
| 2. สำรวจและแบ่งข้อมูล | ตรวจค่าหาย แถวซ้ำ หน่วย และแบ่งชุดให้ตรงกับเวลาใช้งาน |
| 3. สร้าง **baseline** | เช่น ค่าเฉลี่ยจากชุดฝึก เพื่อดูว่าโมเดลใหม่ช่วยได้จริงแค่ไหน |
| 4. ฝึกด้วย **training** | เรียน coefficients, ค่าที่ใช้เติมข้อมูลหาย, ค่าปรับสเกล — **จาก training เท่านั้น** |
| 5. เลือกด้วย **validation** | เทียบ features, degree, alpha ภายใต้เกณฑ์เดียวกัน |
| 6. ประเมินด้วย **test** | ใช้ชุดที่กันไว้รายงานผลครั้งสุดท้าย แล้วติดตามผลหลังใช้งาน |

```
Training ──────► Validation / CV ──────► Test
เรียนรู้พารามิเตอร์    เลือกวิธีและความซับซ้อน     ตรวจผลหลังตัดสินใจแล้ว (ใช้ครั้งเดียว)
```

### หลีกเลี่ยง Data Leakage (ข้อมูลรั่ว)
**Leakage** = โมเดลได้เห็นข้อมูลที่ "ในชีวิตจริงยังไม่มี" ตอนพยากรณ์ ทำให้คะแนนดูดีเกินจริง
- พยากรณ์ยอดพรุ่งนี้ **ห้าม** ใช้ "ยอดเงินจริงตอนปิดร้านพรุ่งนี้" เป็น feature
- อากาศต้องเป็น **พยากรณ์อากาศที่มี ณ เวลานั้น** ไม่ใช่อากาศจริงที่รู้ภายหลัง
- ข้อมูลตามเวลา → **ฝึกจากอดีต ทดสอบกับช่วงถัดไป**
- ข้อมูลหลายแถวต่อคนหรือร้าน → ระวังหน่วยเดียวกันปนข้ามชุด
- แบ่งแบบสุ่มได้ **เมื่อสอดคล้องกับสมมติฐานการใช้งาน** เท่านั้น

> 📌 **คำว่า test ในตัวอย่างการเรียน:** ถ้าเปิดดู error ของชุดหนึ่งแล้วใช้ผลนั้นเลือก degree ซ้ำ ๆ ชุดนั้นกำลังทำหน้าที่เป็น **validation** แล้ว ต้องมี final test อีกชุดที่ไม่ได้ใช้ตัดสินใจ

## 4. Bias–Variance (บท 07 LO4)

Bias และ Variance อธิบายความผิดพลาด **จากคนละมุม** และไม่ใช่ชื่อเรียกของ training error กับ test error โดยตรง

| | **Bias** — คลาดเคลื่อนอย่างเป็นระบบ | **Variance** — ไวต่อชุดฝึก |
|---|---|---|
| วิธีคิด | ฝึกวิธีเดิมจากข้อมูลหลายชุด แล้วเฉลี่ยคำทำนาย ณ x เดิม ถ้าค่าเฉลี่ยยังห่างจากความสัมพันธ์จริง = มี bias | ใช้วิธีเดิมแต่เปลี่ยนชุดฝึก ถ้าคำทำนาย ณ x เดิมเปลี่ยนมาก = variance สูง |
| ตัวอย่าง | ใช้เส้นตรงอธิบายแนวโน้มที่โค้งมาก | polynomial degree สูงที่เส้นเปลี่ยนรูปตามชุดฝึก |
| ข้อควรระวัง | — | ไม่ใช่แค่ "ข้อมูล y กระจายกว้าง" |

$$\text{Expected squared prediction error} = \text{Bias}^2 + \text{Variance} + \text{Noise}$$

- ใช้กับ squared loss ภายใต้ y = f(x) + noise (noise มีค่าเฉลี่ย 0) โดยเฉลี่ยเหนือชุดฝึกและข้อมูลใหม่
- **Noise** = ส่วนที่ลดไม่ได้ **ภายใต้ข้อมูลและกรอบปัญหาที่มีอยู่** (ไม่ได้แปลว่าเก็บ feature เพิ่มแล้วจะช่วยไม่ได้เสมอ)

### ตารางวินิจฉัย

| สิ่งที่สังเกต | ข้อสงสัย | ลองตรวจหรือแก้ |
|---|---|---|
| Train และ validation error **สูงทั้งคู่** (เทียบ baseline/เกณฑ์งาน) | อาจ **underfit** | ตรวจข้อมูล, เพิ่ม feature ที่เกี่ยวข้อง, เพิ่มความยืดหยุ่น |
| Train **ต่ำ** แต่ validation **สูงกว่ามาก** | อาจ **overfit** | ลดความซับซ้อน, ใช้ regularization, เพิ่มข้อมูลที่ตรงงาน |
| ทั้งสอง **ต่ำและใกล้กัน** | สัญญาณที่ดี | แต่ยังต้องตรวจ leakage และ final test |

> ⚠️ ช่องว่างของ error เป็น **สัญญาณให้ตรวจ** ไม่ใช่หลักฐานพิสูจน์ bias/variance จากการแบ่งข้อมูลครั้งเดียว และกราฟรูปตัว U เป็นภาพอธิบายที่พบบ่อย **ไม่ใช่กฎ** ว่าทุกโมเดลต้องเป็นแบบนี้

## 5. แบบทดลอง: เปลี่ยน degree แล้วดูความผิดพลาด

- fit polynomial จริงกับข้อมูลจำลอง **24 จุด (train)** และวัด MSE กับ **validation 80 จุด** ที่คงเดิม
- สถานะเริ่มต้นใน PDF: ชุดฝึก 1/5 (seed 12), **degree 3 → Train MSE 0.0329, Validation MSE 0.0503**

- ปุ่มเปลี่ยนชุดฝึกวนผ่าน 5 ชุดจาก seed คงที่ → ผลซ้ำได้

## 6. Linear Regression และ OLS (บท 08 LO1)

$$\hat y = b_0 + b_1x \qquad\text{หรือ}\qquad \hat y = b_0 + b_1x_1 + b_2x_2 + \dots$$

| สัญลักษณ์ | ความหมาย |
|---|---|
| ŷ | ค่าพยากรณ์ |
| b₀ | **intercept** (ค่าฐาน เมื่อทุก x = 0) |
| b₁, b₂, … | **slope / coefficient** ของแต่ละ feature |

**Ordinary Least Squares (OLS):** เลือก coefficients ที่ทำให้ **ผลรวม residual ยกกำลังสองในชุดฝึกต่ำที่สุด** ภายใต้รูปแบบโมเดลที่กำหนด

**ตัวอย่าง:** เวลาส่ง (นาที) = 10 + 2 × ระยะทาง (กม.)
- ระยะ 5 กม. → 10 + 2×5 = **20 นาที**
- slope 2 → ระยะเพิ่ม 1 กม. ค่าพยากรณ์เพิ่ม 2 นาที
- intercept 10 → ค่าที่โมเดลให้เมื่อระยะ = 0 ซึ่ง **อาจอยู่นอกขอบเขตที่ข้อมูลรองรับ** จึงไม่ควรตีความตรงตัวเสมอ
- กราฟตัวอย่าง: Training MSE = 0.667 นาที²

**Residual** = y − ŷ
- ค่า **บวก** = โมเดลทำนาย **ต่ำกว่า** ค่าจริง
- ค่า **ลบ** = โมเดลทำนาย **สูงกว่า** ค่าจริง

> 💡 เมื่อข้อมูลมี noise การลากเส้นผ่านทุกจุดไม่ใช่เป้าหมาย เป้าหมายคือจับแนวโน้มที่ใช้กับข้อมูลใหม่ได้

## 7. ตัวชี้วัด MAE / MSE / RMSE / R² (บท 08 LO3)

รายงานคะแนน **พร้อมหน่วย ชุดข้อมูลที่ใช้ และ baseline เสมอ** เพราะตัวเลขค่าเดียวไม่ได้เล่าทุกด้านของโมเดล

| ตัวชี้วัด | คำนวณจาก e = y − ŷ | ความหมาย | หน่วย |
|---|---|---|---|
| **MAE** | ค่าเฉลี่ยของ \|e\| | พลาดสัมบูรณ์โดยเฉลี่ย | เดียวกับ y |
| **MSE** | ค่าเฉลี่ยของ e² | เน้นข้อผิดพลาดใหญ่ | y² |
| **RMSE** | √MSE | เน้นข้อผิดพลาดใหญ่ แต่กลับมาเป็นหน่วยของ y | เดียวกับ y |
| **R²** | 1 − Σ(y − ŷ)² / Σ(y − ȳ)² | เทียบกับการใช้ค่าเฉลี่ย y ของชุดที่ประเมิน | ไม่มีหน่วย |

### 🧮 ตัวอย่างคำนวณครบหนึ่งชุด (ทำทีละขั้น)

เวลาจริง y = [10, 20, 30] นาที, ค่าพยากรณ์ ŷ = [12, 18, 26] นาที

| แถว | y | ŷ | e = y − ŷ | \|e\| | e² | y − ȳ (ȳ = 20) | (y − ȳ)² |
|---|---|---|---|---|---|---|---|
| 1 | 10 | 12 | −2 | 2 | 4 | −10 | 100 |
| 2 | 20 | 18 | 2 | 2 | 4 | 0 | 0 |
| 3 | 30 | 26 | 4 | 4 | 16 | 10 | 100 |
| **รวม** | | | | **8** | **24** | | **200** |

- MAE = 8/3 = **2.67 นาที**
- MSE = 24/3 = **8.00 นาที²**
- RMSE = √8 = **2.83 นาที**
- R² = 1 − 24/200 = **0.88** (ไม่มีหน่วย)

**ข้อควรระวังในการอ่านค่า**
- R² = 0.88 **ไม่ได้แปลว่า "ทำนายถูก 88%"** แต่แปลว่า error กำลังสองของโมเดลเหลือ 12% เมื่อเทียบกับการทายด้วยค่าเฉลี่ย
- **R² ติดลบได้** เมื่อพลาดมากกว่าการใช้ค่าเฉลี่ยของชุดประเมิน
- ถ้า y ทุกค่าเท่ากัน ตัวหารของ R² = 0 → ต้องตรวจว่าซอฟต์แวร์จัดการอย่างไร
- RMSE (2.83) > MAE (2.67) เพราะแถวที่ 3 พลาด 4 นาที ซึ่งถูกยกกำลังสองให้หนักขึ้น

**อ่านคะแนนเป็นภาษาผู้ใช้งาน:** "ในข้อมูลวันถัดมาที่กันไว้ โมเดลพลาดเฉลี่ย 2.67 นาที และ RMSE 2.83 นาที" ชัดกว่าการพูดว่า "โมเดลดีมาก"
- ถ้า **ส่งช้าเกินกำหนดแพงกว่าส่งเร็ว** ให้ตรวจ error สองทิศแยกกัน เพราะ MAE/RMSE ลงโทษตามขนาดอย่างเดียว ไม่แยกทิศทาง
- การเทียบ R² กับค่าเฉลี่ยของชุดประเมินเป็นแค่ **นิยามของ metric** ส่วน baseline ที่ใช้พยากรณ์จริงต้องเรียนค่าจาก training เท่านั้น

## 8. fit → predict → score ใน scikit-learn (บท 07 LO5 / บท 08 LO2)

สมมติว่าตารางแบ่งตามเวลาไว้แล้ว ทุก feature พร้อมใช้ ณ เวลาพยากรณ์ และไม่มีค่าหาย

```python
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, mean_squared_error

features = ["distance_km", "orders_in_queue"]
X_train = train[features]              # ตารางสองมิติ
y_train = train["delivery_min"]        # คำตอบเป้าหมาย

model = LinearRegression()
model.fit(X_train, y_train)            # เรียน coefficients จาก training

pred = model.predict(validation[features])
mae  = mean_absolute_error(validation["delivery_min"], pred)
rmse = mean_squared_error(validation["delivery_min"], pred) ** 0.5
r2   = model.score(validation[features], validation["delivery_min"])
```

| เมธอด | หน้าที่ |
|---|---|
| `fit` | เรียนรู้จากข้อมูลฝึก |
| `predict` | คืนคำทำนาย |
| `score` | คืนคะแนน **ตามชนิด estimator** — `LinearRegression` คืน **R²** (ไม่ใช่ accuracy) |

**Simple vs Multiple**
- ใช้ `["distance_km"]` อย่างเดียว = **Simple** Linear Regression
- ใช้ระยะทาง + คิวงาน = **Multiple** Linear Regression
- เทียบกันอย่างยุติธรรมต้องประเมิน **บนชุดเดียวกัน**

**การตีความ coefficient:** ŷ = 8 + 2×ระยะทาง + 1.5×คิวงาน
- coefficient 2 ของระยะทาง = ค่าพยากรณ์เพิ่ม 2 นาทีต่อ 1 กม. **เมื่อ features อื่นคงเดิม**
- ยังไม่พิสูจน์ **เหตุและผล**
- **ห้าม** เทียบขนาด coefficient ข้ามหน่วยตรง ๆ เพื่อจัดอันดับความสำคัญ

**Polynomial** (เช่น x และ x²) ยังเป็นโมเดล **เชิงเส้นใน coefficients** แม้เส้นพยากรณ์จะโค้ง การเพิ่ม degree ทำให้โมเดลยืดหยุ่นขึ้นและอาจ overfit ได้

## 9. อ่าน Residual Plot (บท 08 LO4)

Residual plot ช่วย **ตั้งข้อสงสัย** ต้องอ่านร่วมกับบริบท ไม่ใช่ใช้กราฟเดียวประกาศว่าข้อสมมติผ่านทั้งหมด
(แกนนอน = ค่าพยากรณ์, แกนตั้ง = residual)

| ลักษณะ residual | สิ่งที่ควรตรวจ | แนวทางทดลอง |
|---|---|---|
| กระจายรอบศูนย์ ไม่มีรูปแบบชัด | ไม่มีสัญญาณปัญหาเด่นในกราฟนี้ | ตรวจเพิ่มตามเวลา กลุ่มข้อมูล และข้อผิดพลาดใหญ่ |
| เป็นแนว **โค้ง** | รูปแบบความสัมพันธ์อาจยังไม่ครบ | ลอง polynomial / interaction ที่มีเหตุผล |
| บานเป็น **รูปกรวย** | ความแปรปรวนของ error อาจไม่คงที่ | ตรวจการแปลงเป้าหมาย หรือแบบจำลองความไม่แน่นอน |
| บวกหรือลบต่อกันเป็น **ช่วงเวลา** | อาจมี seasonality / ความสัมพันธ์ตามเวลา | เพิ่ม feature ที่พร้อมใช้ และประเมินด้วย time split |
| **จุดโดด** ห่างจากกลุ่มมาก | ข้อมูลผิด หรือเหตุการณ์จริงที่ต่างออกไป? | ตรวจต้นทางและอิทธิพลก่อนตัดข้อมูล |

> ความปกติ (normality) ของ residual เกี่ยวกับ **การอนุมาน/ช่วงความเชื่อมั่นแบบคลาสสิก** ไม่ใช่เงื่อนไขที่ต้องเป็นจริงจึงจะคำนวณ OLS หรือพยากรณ์ได้

## 10. ปรับโมเดล: Regularization และ Feature Selection (บท 08 LO5)

หลักการ: **ปรับทีละเหตุผล แล้ววัดผลบนข้อมูลเดิม** — เริ่มจากข้อผิดพลาดที่พบ กำหนดสิ่งที่จะเปลี่ยน แล้วเทียบกับ baseline ภายใต้การแบ่งข้อมูลเดียวกัน

### Regularization — ลดการพึ่งพา coefficients ขนาดใหญ่

| | Ridge (L2) | Lasso (L1) |
|---|---|---|
| โทษ | ผลรวม coefficient² | ผลรวม \|coefficient\| |
| ผล | หด coefficients | อาจทำให้บาง coefficient **เป็นศูนย์** |

- alpha มากขึ้น → หดแรงขึ้นโดยทั่วไป **แต่ไม่รับประกัน** ว่าคะแนนบนข้อมูลใหม่จะดีขึ้น
- **ปรับสเกล features ก่อน** ใช้ penalty และ fit scaler จาก **training เท่านั้น**
- ใช้ **pipeline** ให้ preprocessing อยู่ในขั้นตอนฝึก
- เลือก alpha ด้วย **validation/CV ไม่ใช่ final test**

```python
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Ridge

ridge = make_pipeline(StandardScaler(), Ridge(alpha=1.0))
ridge.fit(X_train, y_train)
pred = ridge.predict(validation[features])
# เทียบ MAE/RMSE กับ LinearRegression บน validation เดิม
```

### Feature Selection
- เลือกตัวแปรที่ **มีเหตุผล** และ **มีจริง ณ เวลาพยากรณ์** แล้วทดสอบบน validation
- ตัด feature ไปเรื่อย ๆ จนคะแนนบน test ที่เปิดดูซ้ำดีขึ้น = **กำลังปรับโมเดลให้เข้ากับ test** (test ไม่เป็นอิสระแล้ว)
- features ที่สัมพันธ์กันมาก → coefficients อาจไม่เสถียร

### วงรอบการปรับปรุง (ตัวอย่าง)
1. residual โค้ง → ลองเพิ่มเทอมกำลังสองที่มีเหตุผล
2. train ดีมากแต่ validation แย่ → ลด degree หรือเพิ่ม penalty
3. feature ใหม่ทำให้ validation ดีขึ้น → ตรวจว่าข้อมูลนั้นมีอยู่จริงตอนพยากรณ์
4. บันทึกสิ่งที่ลองและผลทั้งหมด ไม่เลือกเฉพาะการแบ่งข้อมูลที่ให้คะแนนดี
5. เลือกวิธีเสร็จแล้วจึงประเมิน final test และรายงานข้อจำกัด

## 11. กรณีศึกษา: เวลาส่งพัสดุ และบทบาทของ LLM

**สถานการณ์:** ผู้จัดการต้องรู้เวลาส่งโดยประมาณ **ก่อนรับงาน** (ไม่ใช่หลังส่งเสร็จ)

**กำหนดงานให้ตรวจสอบได้**
- 1 แถว = 1 งานส่ง
- Target = เวลาตั้งแต่รับงานถึงส่งเสร็จ (นาที)
- Features = ระยะทาง, คิวงาน, เวลาเริ่ม, สภาพจราจร **ที่ทราบตอนรับงาน**
- แบ่งตามเวลา และแยกข้อมูลซ้ำ

**เกณฑ์เลือกโมเดล:** เริ่มจาก baseline ของ training → รายงาน MAE/RMSE บน validation → ตรวจช่วงเร่งด่วนและระยะไกลแยก → ตรวจความเสี่ยงจากการประเมินเวลาต่ำเกินไป

| วิธี (ค่าจำลอง) | Train MAE | Validation MAE |
|---|---|---|
| Baseline | 8 นาที | 9 นาที |
| **Linear Regression** | 5 นาที | **6 นาที** |
| Polynomial ซับซ้อน | 1 นาที | 11 นาที |

**อ่านตาราง:**
- Polynomial ซับซ้อน: train ดีมาก (1) แต่ validation แย่ที่สุด (11) แย่กว่าแม้แต่ baseline → **overfit ชัดเจน**
- Linear Regression: validation ดีที่สุด (6) และดีกว่า baseline 3 นาที
- ถ้าใช้ validation MAE เป็นเกณฑ์และปัจจัยอื่นเท่ากัน → **เลือก Linear Regression** แล้วประเมินต่อด้วย final test ข้อมูลนี้ยังไม่พิสูจน์ว่าใช้งานจริงแล้วคุ้มค่า

**สิ่งที่ส่งมอบให้ทีมงาน:** ช่วงเวลาข้อมูล, รุ่นโมเดล, features ที่ใช้, คะแนนพร้อม baseline และกรณีที่พลาดมาก บอกให้ชัดว่าเป็นค่าประมาณ ไม่ใช่เวลารับประกัน หลังใช้งานให้ติดตาม error เมื่อมีค่าจริง และตรวจว่ารูปแบบข้อมูลเปลี่ยนหรือไม่

### LLM ช่วยได้อย่างไร (บท 07 LO6)
- ✅ ช่วยร่างโค้ด อธิบาย error ร่างคำอธิบายผล โดยให้แค่โครงสร้างตารางหรือข้อมูลจำลอง (ไม่ส่งข้อมูลส่วนบุคคล)
- ✅ ตรวจชื่อ API กับเอกสาร, **รันโค้ดเอง**, ตรวจ leakage, คำนวณตัวอย่างเล็กด้วยมือก่อนเชื่อผล
- ❌ ไม่ให้ LLM **แต่งคะแนนทดลอง** หรือสรุปว่าเกิดเหตุและผลจาก coefficient

## 12. ต่อยอด: ข้อมูลรายวันและ Bootstrap

Notebook สาธิตการพยากรณ์ **จำนวนนักปั่นจักรยานรายวัน** จาก features ของวัน สภาพอากาศ และแนวโน้มเวลา

### Feature Engineering ที่คำนึงถึงเวลาพยากรณ์
- วันในสัปดาห์ / วันหยุด → **รู้ล่วงหน้าได้**
- อุณหภูมิหรือฝนจริงทั้งวัน → **ยังไม่รู้ตอนเริ่มวัน**
- ต้องแยกงาน "อธิบายข้อมูลอดีต" ออกจากงาน "พยากรณ์วันพรุ่งนี้" ถ้าเป็นงานพยากรณ์ ให้ใช้เฉพาะข้อมูลที่มีจริงในเวลานั้น

### Dummy ของวันในสัปดาห์กับ intercept
แต่ละวันมีค่า 1 เพียงคอลัมน์เดียว ดังนั้นผลรวมของ dummy ทั้ง 7 = 1 เสมอ ซึ่งซ้ำกับคอลัมน์ intercept พอดี (เรียกว่า dummy variable trap) ทางแก้มี 2 วิธี:
1. ใช้ dummy ครบ 7 วัน + `fit_intercept=False` → แต่ละวันมีค่าฐานของตนเอง
2. ใช้ intercept และ **ตัด dummy หนึ่งวัน** เป็นวันอ้างอิง

→ หลีกเลี่ยงการมีทั้ง intercept และ dummy ครบทุกกลุ่มเมื่อจะตีความ coefficients

### Bootstrap ทำอะไร?
1. (สำหรับแถวที่เป็นอิสระ) สุ่มแถวจาก training **แบบใส่คืน** ให้ได้จำนวนเท่าเดิม
2. ฝึกโมเดลใหม่ในแต่ละรอบ เก็บ coefficient ที่สนใจ
3. ดูการกระจาย / ส่วนเบี่ยงเบนมาตรฐานของ coefficient → อธิบาย **ความไม่แน่นอนจากการสุ่มตัวอย่าง**

⚠️ ข้อควรระวัง
- std จาก bootstrap **ไม่ใช่** ขอบเขตความผิดพลาดของคำทำนายแต่ละวันโดยตรง
- ข้อมูลรายวันพึ่งพากันตามเวลา → ควรใช้ **block bootstrap** หรือวิธีที่คงโครงสร้างเวลา การสุ่มทีละวันแบบอิสระอาจให้ภาพความไม่แน่นอนที่ไม่เหมาะสม

### อ่านผลเชิงสัมพันธ์อย่างระมัดระวัง
coefficient ของอุณหภูมิเป็นบวก = โมเดลให้ค่าพยากรณ์สูงขึ้นเมื่ออุณหภูมิเพิ่ม **โดยคง features อื่นไว้** ไม่ใช่หลักฐานว่าอุณหภูมิเป็นสาเหตุเพียงอย่างเดียว หรือพิสูจน์ผลการลงทุนโครงสร้างพื้นฐาน

## 13. ต่อยอด: ข้อมูลที่รู้คำตอบ และ Cost Function

แนวคิด: **สร้างข้อมูลจากสมการที่เรากำหนดเอง** แล้วตรวจว่าการ fit กู้ความสัมพันธ์กลับมาได้ใกล้แค่ไหน (มี noise แล้วไม่ต้องคาดหวังค่าตรงเป๊ะ)

$$y = ax + b + \varepsilon,\quad \varepsilon \text{ มีค่าเฉลี่ย } 0$$

```python
import numpy as np
rng = np.random.default_rng(123)
x = rng.uniform(0, 10, size=50)
noise = rng.normal(loc=0, scale=1, size=50)
y = 2 * x - 3 + noise          # ความชัน a = 2, intercept b = -3
X = x.reshape(-1, 1)           # 50 แถว, 1 feature (sklearn ต้องการ 2 มิติ)
```

- 2x − 3 เขียนเป็น ax + b ได้โดย a = 2, **b = −3**
- ⚠️ ถ้า noise มีค่าเฉลี่ย 0.5 (ไม่ใช่ 0) ค่าเฉลี่ยของ y เมื่อรู้ x จะเป็น 2x − 2.5 → ต้องแยก "ค่าฐานในโค้ด" ออกจาก "ค่าฐานของความสัมพันธ์เฉลี่ย" (โมเดลจะเรียน intercept ได้ประมาณ −2.5 ไม่ใช่ −3)

**Seed:** ทำให้สร้างลำดับสุ่มซ้ำได้ (เมื่อใช้ generator วิธีเดิมและลำดับคำสั่งเดิม) แต่ **ไม่ได้** ทำให้ข้อมูลไร้ noise หรือโมเดลแม่นขึ้น
❌ อย่าเขียน `np.random.seed = 123` เพราะเป็นการเขียนทับชื่อฟังก์ชัน (ไม่ได้ตั้ง seed) ให้ใช้ `rng = np.random.default_rng(123)` แทน (หรือ `np.random.seed(123)` แบบเรียกฟังก์ชัน)

### Cost Function — ให้คะแนนเส้นแต่ละเส้น
- **SSE** = Σ(y − ŷ)² (ผลรวม)
- **MSE** = SSE / n (ค่าเฉลี่ย)
- บนข้อมูลชุดเดียวกันที่ n คงที่และยังไม่มี penalty → ทั้งสองเลือก **เส้นที่ดีที่สุดเส้นเดียวกัน** (หารด้วยค่าคงที่ไม่เปลี่ยนจุดต่ำสุด)
- เมื่อรวม penalty ต้องระบุว่าหารด้วย n หรือไม่ เพราะความหมายของ alpha จะต่างกัน (SSE + α·penalty กับ MSE + α·penalty ให้ผลเท่ากันเมื่อ alpha ต่างกัน n เท่า)

**ภาพเชิงเรขาคณิต:** การเลื่อน slope/intercept = การเดินบนพื้นผิว cost ในแกนพารามิเตอร์
- สำหรับ OLS ที่ features คงที่ พื้นผิว squared-error เป็น **convex** → ค่าต่ำสุดเฉพาะที่ = ค่าต่ำสุดโดยรวม
- แต่คำตอบอาจ **ไม่เป็นเอกลักษณ์ (ไม่ unique)** ถ้า design matrix มีคอลัมน์ที่พึ่งพากัน (เช่น dummy trap ในหัวข้อ 12)

## 14. ต่อยอด: Basis Functions

**Basis function** = ฟังก์ชันที่ใช้สร้าง features ใหม่จาก x เดิม แล้วให้ Linear Regression เรียนน้ำหนักของแต่ละ feature

### Polynomial basis
- x → [x, x², x³] เช่น x = 2 → [2, 4, 8]
- `PolynomialFeatures(3, include_bias=False)` แล้วให้โมเดลมี intercept เอง

### Gaussian basis

$$\varphi_j(x) = \exp\!\left[-\tfrac12\left(\frac{x-c_j}{\sigma}\right)^2\right]
\qquad \hat y = b_0 + b_1\varphi_1(x) + \dots + b_n\varphi_n(x)$$

- แต่ละ feature ให้ค่า **สูงสุด (= 1) เมื่อ x อยู่ที่ศูนย์กลาง cⱼ** และลดลงเมื่อห่างออกไป
- σ (ความกว้าง) ควบคุมความเร็วในการลดลง
- ค่า feature **ไม่ใช่ความน่าจะเป็น**
- เมื่อกำหนด centers และ widths ไว้แล้ว โมเดลยัง **เชิงเส้นใน coefficients** แม้จะไม่เป็นเส้นตรงใน x
- รูปร่างตาราง: (จำนวนแถว, 1) → หลังแปลงด้วย N bases → **(จำนวนแถว, N)**

**ตัวอย่างในกราฟ:** N = 5 บนช่วง 0–10 → ระยะห่าง centers 2.5 → σ = 1.25 และที่ x = 5 ค่า basis ตรงกลาง = 1

⚠️ ในคลาสของ Notebook: **σ = width_factor × ระยะห่างระหว่าง centers** (ไม่ใช่ σ = width_factor ตรง ๆ) ถ้าเปลี่ยน N โดยคง factor ไว้ ความกว้างจริงจะเปลี่ยนตามไปด้วย

**การใช้งานจริง:** ถ้าความต้องการเพิ่มเฉพาะช่วงอุณหภูมิหนึ่ง Gaussian bases อาจอธิบายรูปแบบเฉพาะช่วงได้ดี แต่ควรเทียบกับโมเดลง่ายก่อน และ **ระวังการพยากรณ์นอกช่วง training** เพราะ features จะเข้าใกล้ 0 เมื่อ x อยู่ไกลจากทุก center (ค่าพยากรณ์จะหดลงหา intercept)

## 15. ต่อยอด: เปรียบเทียบ OLS / Ridge / Lasso อย่างยุติธรรม

ถ้าเปลี่ยน **ทั้ง** จำนวน basis **และ** วิธีลงโทษพร้อมกัน จะบอกไม่ได้ว่าผลที่ต่างเกิดจากส่วนใด → **คงสิ่งอื่นให้เท่ากัน เปลี่ยนทีละอย่าง**

| วิธี | สิ่งที่ลดให้ต่ำ | สิ่งที่สังเกต |
|---|---|---|
| OLS | Squared error | อาจมี coefficients ขนาดใหญ่ที่หักล้างกัน |
| Ridge | Squared error + L2 | หด coefficients โดยทั่วไปไม่เป็นศูนย์พอดี |
| Lasso | Squared error + L1 | บาง coefficients อาจเป็นศูนย์ |

**ลำดับการทดลองที่อ่านเหตุผลได้**
1. แบ่ง training / validation / test แล้ว **ตรึงการแบ่งเดิม** สำหรับทุกวิธี
2. ใช้จำนวน basis, centers, widths **ชุดเดียวกัน** (ส่วนที่ต้อง fit เรียนจาก training)
3. fit scaler ใน training และใช้ขั้นตอนเดียวกันทุกวิธี
4. เทียบบน validation เดิม **ปรับ alpha ภายในแต่ละวิธี** (alpha เลขเดียวกันของ Ridge กับ Lasso ไม่ได้แปลว่าลงโทษแรงเท่ากัน)
5. บันทึกทั้ง error และ coefficients แล้วประเมิน final test หลังเลือกวิธีแล้ว

**ตัวอย่างสมมติ:** OLS train MSE 0.01 / validation 0.80; Ridge 0.04 / 0.12 → ใช้ validation MSE เป็นเกณฑ์ **เลือก Ridge** แม้ training error สูงกว่า (OLS มีช่องว่าง train–validation กว้างมาก ซึ่งเป็นสัญญาณ overfit)

⚠️ **coefficients ใหญ่ไม่ได้พิสูจน์ว่า overfit** — ค่าใหญ่และสลับเครื่องหมายอาจเกิดจาก features ที่สัมพันธ์กันหรือสเกลต่างกัน ต้องดูผลบนข้อมูลใหม่และความไวเมื่อเปลี่ยนชุดฝึกประกอบ และการเพิ่ม penalty ไม่รับประกันว่าผลจะดีขึ้นเสมอ

### ข้อ 1 — ระบบต้องทำนายเวลาส่งพัสดุเป็นนาทีจากงานในอดีตที่มีเวลาส่งจริง เป็นงานแบบใด?
ก. Supervised regression ข. Unsupervised clustering ค. Reinforcement learning

**✅ คำตอบ: ก. Supervised regression**

ต้องตัดสินใจ 2 เรื่อง:
1. **ข้อมูลมีคำตอบหรือไม่?** มี "เวลาส่งจริง" ในอดีต ซึ่งเป็น label (y) ให้เรียนรู้ → **Supervised**
2. **คำตอบเป็นอะไร?** เป็น **จำนวนนาที** ซึ่งเป็นปริมาณตัวเลข → **Regression**

ตัวเลือกอื่นผิดเพราะ
- ข. Clustering ใช้เมื่อ **ไม่มี label** และต้องการหากลุ่ม แต่โจทย์นี้มีคำตอบให้ และต้องการตัวเลข ไม่ใช่กลุ่ม
- ค. Reinforcement ใช้เมื่อ agent ต้องเลือก **การกระทำ** แล้วได้รางวัลสะสมตามเวลา โจทย์นี้ไม่มีการกระทำหรือรางวัล มีแค่การทำนายค่า

💡 ถ้าเปลี่ยนคำถามเป็น "จะส่งทันกำหนดหรือไม่" จะกลายเป็น Supervised **classification** แม้ใช้ข้อมูลเดิม

---

### ข้อ 2 — ทีมดู error ของชุดหนึ่งทุกครั้งเพื่อเลือก degree ชุดนี้ทำหน้าที่ใด?
ก. Training ข. Validation ค. Final test ที่ยังเป็นอิสระจากการเลือก

**✅ คำตอบ: ข. Validation**

หน้าที่ของชุดข้อมูลถูกกำหนดจาก **วิธีที่เราใช้มัน** ไม่ใช่จากชื่อที่ตั้ง
- ชุดที่ใช้ **เลือก** hyperparameter (degree, alpha, features) คือ **validation**
- เมื่อเราดูผลแล้วเลือก degree ที่ดีที่สุดบนชุดนี้ซ้ำ ๆ ข้อมูลชุดนี้ได้ "รั่ว" เข้าไปในการตัดสินใจแล้ว ผลบนชุดนี้จึงมีแนวโน้มดูดีกว่าความเป็นจริง

ตัวเลือกอื่นผิดเพราะ
- ก. Training ใช้เรียน coefficients (ขั้น `fit`) ไม่ได้ใช้เปรียบเทียบ degree
- ค. ชุดนี้ **ไม่เป็นอิสระแล้ว** เพราะถูกใช้ตัดสินใจไปแล้ว → ต้องกัน final test อีกชุดที่ไม่เคยใช้ตัดสินใจ ไว้รายงานผลครั้งสุดท้าย

---

### ข้อ 3 — Train error ต่ำมาก แต่ validation error สูงกว่ามาก ควรตรวจเรื่องใดก่อน?
ก. อาจ overfit หรือข้อมูลสองชุดมีความแตกต่างกัน ข. โมเดลถูกต้องแน่นอน ค. เพิ่ม degree เสมอ

**✅ คำตอบ: ก. อาจ overfit หรือข้อมูลสองชุดมีความแตกต่างกัน**

ช่องว่างกว้างระหว่าง train กับ validation มีสาเหตุที่เป็นไปได้หลัก 2 อย่าง
1. **Overfitting:** โมเดลจำรายละเอียดหรือ noise ของชุดฝึก ใช้กับข้อมูลใหม่ไม่ได้
2. **ข้อมูลสองชุดต่างกัน:** เช่น validation มาจากช่วงเวลาหรือสภาพที่ต่างไป (distribution shift) หรือแบ่งข้อมูลผิด

ช่องว่างเป็น **สัญญาณให้ตรวจ** ไม่ใช่ข้อพิสูจน์จากคะแนนอย่างเดียว

ตัวเลือกอื่นผิดเพราะ
- ข. train error ต่ำไม่ได้แปลว่าโมเดลดี และ validation ที่แย่กว่ามากเป็นสัญญาณอันตราย
- ค. การเพิ่ม degree ทำให้โมเดลซับซ้อนขึ้น ซึ่ง **ทำให้ overfit หนักขึ้น** ควรลด degree หรือเพิ่ม regularization แทน

---

### ข้อ 4 — คง degree เดิม แล้วฝึกจากหลายชุด คำทำนายที่ x เดิมเปลี่ยนมาก สะท้อนแนวคิดใด?
ก. Variance ของวิธีเรียนรู้ ข. ค่าเฉลี่ยของ y ค. หน่วยของ RMSE

**✅ คำตอบ: ก. Variance ของวิธีเรียนรู้**

นิยามของ variance คือ **ความไวของคำทำนายต่อการเปลี่ยนชุดฝึก** โดยดูที่ input เดิม
- ใช้วิธีเดิม (degree เดิม) และจุด x เดิม เปลี่ยนแค่ชุดฝึก → ถ้าเส้นแกว่งมาก = variance สูง
- มักพบใน degree สูง เพราะเส้นเปลี่ยนรูปตาม noise ของแต่ละชุด

ตัวเลือกอื่นผิดเพราะ
- ข. ค่าเฉลี่ยของ y เป็นสถิติของข้อมูล ไม่ได้วัดความไวของโมเดล
- ค. หน่วยของ RMSE คือหน่วยเดียวกับ y ไม่เกี่ยวกับความแปรปรวนของคำทำนาย

💡 เทียบกับ **bias:** ถ้าเฉลี่ยคำทำนายจากหลายชุดฝึกแล้ว **ค่าเฉลี่ย** ยังห่างจากความสัมพันธ์จริง = bias

### ข้อ 5 — ใน ŷ = 10 + 2x เมื่อ x = 5 กม. ค่าพยากรณ์คือเท่าใด?
ก. 12 นาที ข. 20 นาที ค. 25 นาที

**✅ คำตอบ: ข. 20 นาที**

แทนค่า: ŷ = 10 + 2 × 5 = 10 + 10 = **20 นาที** (ต้องระบุหน่วยของผลลัพธ์ด้วย)

ตัวเลือกผิดที่มักเกิดจากการคำนวณพลาด
- ก. 12 = 10 + 2 (ลืมคูณด้วย x)
- ค. 25 = อาจสับสนเป็น 5 × 5 หรือ (10 + 2.5)×2

### ข้อ 6 — ถ้า MSE = 9 นาที² ค่า RMSE เท่ากับเท่าใด?
ก. 3 นาที ข. 9 นาที ค. 81 นาที²

**✅ คำตอบ: ก. 3 นาที**

RMSE = √MSE = √9 = **3** และการถอดรากทำให้หน่วยกลับจาก นาที² เป็น **นาที**

ตัวเลือกอื่นผิดเพราะ
- ข. 9 คือค่า MSE เดิม และหน่วยต้องเป็นนาที² ไม่ใช่นาที
- ค. 81 = 9² คือการยกกำลังสองซ้ำ ซึ่งเป็นทิศทางตรงข้ามกับที่ต้องทำ

### ข้อ 7 — `LinearRegression.score(X, y)` คืนคะแนนใด?
ก. Accuracy เสมอ ข. MAE ค. R²

**✅ คำตอบ: ค. R²**

ใน scikit-learn ความหมายของ `score` **ขึ้นกับชนิด estimator**
- Regressor (เช่น `LinearRegression`, `Ridge`) → **R²**
- Classifier (เช่น `LogisticRegression`) → **accuracy** (เฉลี่ย)

ตัวเลือกอื่นผิดเพราะ
- ก. Accuracy ใช้กับงานจำแนกประเภท และไม่ใช่ค่ากลางของทุกโมเดล
- ข. ถ้าต้องการ MAE ต้องเรียก `mean_absolute_error` แยกเอง

### ข้อ 8 — residual มีรูปโค้งอย่างเป็นระบบ ข้อใดเป็นแนวทางทดลองที่มีเหตุผล?
ก. ลองเพิ่มเทอมโค้งที่เกี่ยวข้อง แล้วเทียบบน validation ข. ลบทุกจุดที่ residual ไม่เป็นศูนย์ ค. ใช้ test เลือก degree ไปเรื่อย ๆ

**✅ คำตอบ: ก.**

รูปโค้งบอกว่า **โมเดลยังอธิบายรูปแบบความสัมพันธ์ได้ไม่ครบ** (เช่น ใช้เส้นตรงกับความสัมพันธ์โค้ง) จึงควร
1. เพิ่มเทอมที่มีเหตุผล เช่น x² หรือ interaction
2. เปรียบเทียบผลบน **validation** (ไม่ใช่ test)

ตัวเลือกอื่นผิดเพราะ
- ข. ข้อมูลที่มี noise ย่อมมี residual ไม่เป็นศูนย์เกือบทุกจุด การลบทิ้งทำลายข้อมูลและบิดเบือนผล ปัญหาอยู่ที่รูปแบบโมเดล ไม่ใช่ข้อมูล
- ค. การเลือก degree จาก test ซ้ำ ๆ ทำให้ test กลายเป็น validation (ย้อนกลับไปดูข้อ 2) จึงไม่เหลือชุดที่ประเมินได้อย่างเป็นอิสระ

---

### ข้อ 9 — LLM สร้างโค้ดได้โดยไม่มี error ข้อใดควรทำต่อ?
ก. รายงานว่าผลถูกต้องทันที ข. ตรวจการแบ่งข้อมูล สูตร และผลกับตัวอย่างที่รู้คำตอบ ค. ให้ LLM สร้างคะแนนผลทดลองแทนการรัน

**✅ คำตอบ: ข.**

"โค้ดรันได้" ≠ "โค้ดถูกหลัก" โค้ดที่รันผ่านอาจยังผิดได้ เช่น
- fit scaler กับข้อมูลทั้งหมดก่อนแบ่ง (leakage)
- ใช้สูตรผิด เช่น ลืมถอดรากตอนคำนวณ RMSE
- ใช้ feature ที่ยังไม่มีตอนพยากรณ์

วิธีตรวจ: ทดสอบกับข้อมูลที่รู้คำตอบ (เช่น ข้อมูลจำลอง y = 2x − 3 ในหัวข้อ 13) หรือคำนวณตัวอย่างเล็กด้วยมือ (เช่น ตัวอย่าง MAE = 2.67 ในหัวข้อ 7) แล้วเทียบกับผลโค้ด

ตัวเลือกอื่นผิดเพราะ
- ก. ยังไม่มีหลักฐานว่าผลถูก
- ค. เป็นการ **แต่งผลทดลอง** ซึ่งผิดหลักวิชาการโดยตรง

### ข้อ 10 — ใน Multiple Linear Regression จะตีความ coefficient ของระยะทางอย่างไร?
ก. ผลต่อค่าพยากรณ์เมื่อระยะทางเพิ่มหนึ่งหน่วย โดยคง features อื่น ข. ผลเชิงสาเหตุที่พิสูจน์แล้ว ค. ความน่าจะเป็นที่คำทำนายถูก

**✅ คำตอบ: ก.**

ตัวอย่าง ŷ = 8 + 2×ระยะทาง + 1.5×คิวงาน → ระยะเพิ่ม 1 กม. ค่าพยากรณ์เพิ่ม 2 นาที **เมื่อคิวงานคงเดิม**
คำว่า "คง features อื่น" สำคัญมาก เพราะใน Multiple Regression coefficient แต่ละตัวถูกปรับด้วยตัวแปรอื่นในโมเดลแล้ว

ตัวเลือกอื่นผิดเพราะ
- ข. Regression จากข้อมูลสังเกตการณ์แสดง **ความสัมพันธ์ในโมเดล** ไม่ได้พิสูจน์เหตุและผลโดยอัตโนมัติ (อาจมีตัวแปรกวนที่ไม่ได้ใส่ในโมเดล)
- ค. coefficient มีหน่วย (นาทีต่อ กม.) ไม่ใช่ความน่าจะเป็น

### ข้อ 11 — ข้อมูลรายวันมีความสัมพันธ์ตามเวลา ข้อใดเหมาะกับการประเมินความไม่แน่นอนมากกว่า?
ก. สุ่มแต่ละวันแบบอิสระโดยไม่ตรวจโครงสร้าง ข. พิจารณา block bootstrap ที่รักษาช่วงเวลาต่อเนื่อง ค. สรุปว่าค่า std ของ coefficient คือ MAE

**✅ คำตอบ: ข.**

Bootstrap แบบปกติสมมติว่าแต่ละแถว **เป็นอิสระต่อกัน** แต่ข้อมูลรายวันไม่เป็นเช่นนั้น (วันนี้คล้ายเมื่อวาน มีรอบสัปดาห์ และฤดูกาล)
- การสุ่มทีละวันจะทำลายความต่อเนื่องนี้ และมักทำให้ประเมินความไม่แน่นอน **ต่ำเกินจริง**
- **Block bootstrap** สุ่มเป็น "ก้อน" ของวันต่อเนื่อง (เช่น ทีละ 7 หรือ 14 วัน) จึงรักษาความพึ่งพาตามเวลาไว้ได้บางส่วน ทั้งนี้ต้องเลือกวิธีและขนาดก้อนให้เหมาะกับข้อมูล

ตัวเลือกอื่นผิดเพราะ
- ก. ละเลยโครงสร้างเวลา ซึ่งเป็นข้อสมมติที่ไม่เป็นจริงสำหรับข้อมูลนี้
- ค. std ของ coefficient วัด **ความไม่แน่นอนของพารามิเตอร์** ส่วน MAE วัด **ความผิดพลาดของคำทำนาย** เป็นคนละสิ่ง และมีหน่วยต่างกันด้วย

### ข้อ 12 — โมเดล A มี validation MAE 4 นาที B มี 7 นาที บนชุดเดียวกัน ถ้าใช้ MAE เป็นเกณฑ์และปัจจัยอื่นเท่ากัน ควรเลือกตัวใด?
ก. A แล้วประเมินด้วย final test ข. B เพราะ error มากกว่า ค. ตัดสินจากตัวเลขนี้ไม่ได้เลย

**✅ คำตอบ: ก.**

- MAE เป็น error ยิ่ง **ต่ำยิ่งดี** A พลาดเฉลี่ยน้อยกว่า B 3 นาที บน **ชุดเดียวกัน** จึงเทียบกันได้อย่างยุติธรรม
- แต่ validation ถูกใช้เลือกแล้ว จึงต้องยืนยันด้วย **final test** ก่อนรายงาน และผลนี้ก็ยังไม่รับประกันผลในอนาคต (ต้องติดตามหลังใช้งาน)

ตัวเลือกอื่นผิดเพราะ
- ข. อ่านทิศทางของ metric กลับด้าน
- ค. โจทย์กำหนดเกณฑ์และบอกว่าปัจจัยอื่นเท่ากันแล้ว จึงตัดสินได้ (ในงานจริงอาจดูปัจจัยอื่นประกอบ เช่น ความซับซ้อน หรือ error ช่วงเร่งด่วน)

### ข้อ 13 — ใน y = 2x − 3 + noise เมื่อ noise มีค่าเฉลี่ยศูนย์ intercept ของความสัมพันธ์เฉลี่ยคือเท่าใด?
ก. 3 ข. −3 ค. 0

**✅ คำตอบ: ข. −3**

- ค่าคาดหวัง: E[y | x] = 2x − 3 + E[noise] = 2x − 3 + 0 = **2x − 3**
- เทียบกับ ax + b ได้ a = 2 และ **b = −3**
- เมื่อ fit ด้วยข้อมูลที่มี noise ค่าที่ได้จะใกล้ −3 แต่ไม่เป๊ะ (เช่น −2.9 หรือ −3.1)

ตัวเลือกอื่นผิดเพราะ
- ก. ลืมเครื่องหมายลบ
- ค. เข้าใจผิดว่า noise ค่าเฉลี่ย 0 ทำให้ intercept เป็น 0 จริง ๆ แล้ว noise ค่าเฉลี่ย 0 แค่ไม่เปลี่ยน intercept

💡 ถ้า noise มีค่าเฉลี่ย 0.5 → intercept ของความสัมพันธ์เฉลี่ยจะเป็น −3 + 0.5 = −2.5

### ข้อ 14 — บนข้อมูลชุดเดียวกัน 50 แถว ไม่มี penalty ถ้า SSE = 100 จะได้ MSE เท่าใด?
ก. 2 ข. 50 ค. 100

**✅ คำตอบ: ก. 2**

MSE = SSE / n = 100 / 50 = **2**

- การหารด้วย n (ค่าคงที่) **ไม่เปลี่ยนเส้นที่ทำให้ error ต่ำสุด** เพราะเป็นแค่การปรับสเกลของ cost ทั้งพื้นผิว ดังนั้น OLS จะได้เส้นเดียวกันไม่ว่าใช้ SSE หรือ MSE

ตัวเลือกอื่นผิดเพราะ
- ข. 50 คือจำนวนแถว n ไม่ใช่ MSE
- ค. 100 คือ SSE (ยังไม่ได้หาร)

### ข้อ 15 — Centers ห่างกัน 2.5 และ GaussianFeatures ใช้ width_factor = 0.5 ความกว้างจริง σ เป็นเท่าใด?
ก. 0.5 ข. 1.25 ค. 2.5

**✅ คำตอบ: ข. 1.25**

คลาสใน Notebook คำนวณ **σ = width_factor × ระยะห่างระหว่าง centers** = 0.5 × 2.5 = **1.25**

ตัวเลือกอื่นผิดเพราะ
- ก. 0.5 คือ factor ซึ่งเป็นแค่ตัวคูณ ไม่ใช่ความกว้างจริง (นี่คือกับดักหลักของข้อนี้)
- ค. 2.5 คือระยะห่าง centers ยังไม่ได้คูณด้วย factor

💡 ผลที่ตามมา: ถ้าเพิ่ม N (centers ถี่ขึ้น) แต่คง factor 0.5 ไว้ ระยะห่างจะเล็กลง σ จะเล็กลงตาม → basis แต่ละตัวแคบลง โมเดลยืดหยุ่นขึ้นและเสี่ยง overfit มากขึ้น

### ข้อ 16 — ต้องการตรวจผลของ penalty โดยตรง ควรเปรียบเทียบโมเดลอย่างไร?
ก. เปลี่ยนจำนวน basis และชุด validation ของแต่ละวิธี ข. คง basis, preprocessing และชุดข้อมูลไว้ แล้วเปรียบเทียบ penalty ค. เลือกวิธีจาก coefficient ที่ดูเล็กที่สุดอย่างเดียว

**✅ คำตอบ: ข.**

หลัก **controlled experiment (เปลี่ยนทีละตัวแปร)**: ถ้าต้องการรู้ผลของ penalty ต้องคงสิ่งอื่นทั้งหมดไว้ ได้แก่ การแบ่งข้อมูล, basis/centers/widths, scaler และขั้นตอน preprocessing จากนั้นเปรียบเทียบ OLS / Ridge / Lasso บน validation เดียวกัน (โดยจูน alpha ภายในแต่ละวิธี)

ตัวเลือกอื่นผิดเพราะ
- ก. เปลี่ยนหลายอย่างพร้อมกัน จึงแยกไม่ได้ว่าผลต่างมาจาก basis, จาก validation ที่ต่างกัน หรือจาก penalty
- ค. coefficient เล็กไม่ได้แปลว่าทำนายดี (ถ้า alpha ใหญ่มาก coefficient เกือบเป็นศูนย์หมด โมเดลจะ underfit) ต้องวัดคุณภาพจาก error บน validation

## 17. แนวคำตอบคำถามปลายเปิด

### 17.1 คำถาม 3 ข้อในแบบทดลอง degree (หัวข้อ 5)

**1) เมื่อเพิ่ม degree ค่า training MSE เปลี่ยนอย่างไร?**
โดยทั่วไป **ลดลง (หรืออย่างน้อยไม่เพิ่ม)** เพราะ polynomial degree สูงกว่ามี degree ต่ำกว่าเป็นกรณีพิเศษ (ตั้ง coefficient ส่วนที่เพิ่มเป็น 0 ก็ได้โมเดลเดิม) และ OLS หาค่าต่ำสุดบนชุดฝึก จึงทำได้ไม่แย่ลง เมื่อ degree สูงมาก เส้นจะเริ่มวิ่งผ่านจุดฝึกจนเกือบเป็นศูนย์

**2) degree ที่ training MSE ต่ำสุด เป็นตัวที่ validation MSE ต่ำสุดด้วยหรือไม่?**
**มักไม่ใช่** degree สูงสุดได้ training MSE ต่ำสุด แต่ validation MSE มักต่ำสุดที่ degree กลาง ๆ (ในแบบทดลองนี้ degree 3 ให้ train 0.0329 / validation 0.0503) เมื่อ degree สูงขึ้นอีก validation จะเริ่มแย่ลงเพราะ overfit → **ห้ามเลือกโมเดลจาก training error**

**3) คง degree เดิมแล้วเปลี่ยนชุดฝึก เส้นเปลี่ยนมากแค่ไหน?**
- degree ต่ำ (เช่น 1): เส้นแทบไม่เปลี่ยน (variance ต่ำ) แต่ห่างจากเส้นจริงอย่างเป็นระบบ (bias สูง)
- degree กลาง: เปลี่ยนเล็กน้อยและใกล้เส้นจริง
- degree สูง: เปลี่ยนมาก โดยเฉพาะบริเวณขอบช่วง x ที่มีข้อมูลน้อย (variance สูง)

ทั้งนี้เป็นการสังเกตจาก 5 ชุด ไม่ใช่การประมาณ bias²/variance อย่างแม่นยำ

### 17.2 คำถามทบทวน 6 ข้อ (ตอบโดยใช้กรณีเวลาส่งพัสดุ)

1. **ชนิดงาน:** ต้องการ **ตัวเลข** (นาที) → Supervised Regression
2. **feature พร้อมใช้หรือไม่:** ระยะทาง คิวงาน เวลาเริ่ม และจราจร **ณ ตอนรับงาน** รู้ได้จริง ส่วน "จราจรจริงระหว่างส่ง" หรือ "เวลาถึงจริง" ห้ามใช้เพราะเป็น leakage
3. **การแบ่งชุด:** แบ่งตามเวลา — ช่วงเก่า = training (fit coefficients และ scaler), ช่วงถัดไป = validation (เลือก features/degree/alpha), ช่วงล่าสุดที่กันไว้ = final test (รายงานครั้งเดียว)
4. **หน่วยและ baseline:** MAE/RMSE มีหน่วยเป็น **นาที** เช่น Linear Regression validation MAE 6 นาที เทียบ baseline 9 นาที = ดีขึ้น 3 นาที (≈ 33%)
5. **residual:** ถ้าโค้ง ให้ลองเทอม x² ของระยะทาง, ถ้าเป็นช่วงตามเวลา ให้เพิ่ม feature ชั่วโมงเร่งด่วน, ถ้าบานเป็นกรวยที่ระยะไกล ให้ลองแปลง target เป็น log — ทุกการแก้ต้องเทียบบน **validation** ไม่เปิด test ซ้ำ
6. **ขอบเขตข้อสรุป:** ข้อมูลแสดงได้ว่าโมเดลพลาดเฉลี่ยประมาณเท่าใดในช่วงเวลาที่ทดสอบ แต่ยังพิสูจน์ไม่ได้ว่า "ระยะทางเป็นสาเหตุ" หรือว่าโมเดลจะยังแม่นเมื่อรูปแบบข้อมูลเปลี่ยน (เช่น ฤดูฝน หรือพื้นที่ใหม่)

## 18. สรุปรวบยอด (Cheat Sheet)

**แนวคิดหลัก 10 ข้อ**
1. เลือกชนิดงานจาก **เป้าหมาย** (ตัวเลข / ประเภท / กลุ่ม / รางวัล) ไม่ใช่จากข้อมูลนำเข้า
2. ใช้ feature ที่ **มีจริง ณ เวลาพยากรณ์** เท่านั้น เพื่อกัน leakage
3. **Train** เรียนพารามิเตอร์ / **Validation** เลือกวิธี / **Test** รายงานครั้งเดียว
4. ทุกอย่างที่เรียนจากข้อมูล (scaler, ค่าเติมค่าหาย) ต้อง fit จาก **training เท่านั้น** ใช้ pipeline ช่วย
5. **Bias** = ผิดอย่างเป็นระบบ, **Variance** = ไวต่อชุดฝึก, Error = Bias² + Variance + Noise
6. Train ต่ำ + Val สูง → สงสัย overfit, ทั้งคู่สูง → สงสัย underfit
7. รายงาน metric **พร้อมหน่วย ชุดข้อมูล และ baseline**
8. `LinearRegression.score` = **R²** และ R² ≠ "% ที่ถูก" และติดลบได้
9. Coefficient = ผลเมื่อ feature เพิ่ม 1 หน่วย **โดยคงตัวอื่น** ไม่ใช่เหตุและผล
10. เทียบวิธีอย่างยุติธรรม = **เปลี่ยนทีละอย่าง** บน validation เดิม

**สูตรด่วน**

| | สูตร |
|---|---|
| Linear model | ŷ = b₀ + b₁x₁ + … |
| Residual | e = y − ŷ (บวก = ทายต่ำไป) |
| MAE / MSE / RMSE | mean\|e\| / mean(e²) / √MSE |
| R² | 1 − Σe² / Σ(y − ȳ)² |
| SSE → MSE | MSE = SSE / n |
| Ridge / Lasso | + α Σβ² / + α Σ\|β\| |
| Gaussian basis | φ(x) = exp[−½((x − c)/σ)²], σ = factor × spacing |
