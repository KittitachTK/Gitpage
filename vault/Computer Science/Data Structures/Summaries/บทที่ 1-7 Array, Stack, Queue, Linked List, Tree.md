# บทที่ 1 · Introduction to Data Structures

## 1.1 ชนิดข้อมูล (Data Type)

**Primitive Data Type** — ชนิดข้อมูลพื้นฐานที่ภาษามีมาให้ในตัว (built-in)
- Integer, Boolean, Floating point, Character / String

**Non-Primitive Data Type** — สร้างจากการรวมกันของ primitive type + operations เป็นอิสระจากการ implement
- **Linear Data:** List / Array / Stack / Queue
- **Non-Linear Data:** Tree / Graph

## 1.2 รูปแบบการจัดสรรหน่วยความจำ

| แบบ | ลักษณะ | โครงสร้างที่ใช้ |
|---|---|---|
| **Sequential Allocation** | จองต่อเนื่องเป็นกลุ่ม, กำหนดขนาดล่วงหน้า, ข้อมูลขนาดเท่ากัน, เข้าถึงเร็ว | Array |
| **Linked Allocation** | จองเมื่อต้องการ, กระจายตัวได้, เชื่อมกันด้วยลิงก์ | Linked List |

## 1.3 วัตถุประสงค์ของโครงสร้างข้อมูล

1. **Correctness** — ทำงานถูกต้องกับ input ทุกรูปแบบใน domain ที่สนใจ
2. **Efficiency** — ประมวลผลเร็ว ใช้ทรัพยากร (หน่วยความจำ) ไม่มากเกินไป

## 1.4 การวิเคราะห์ประสิทธิภาพ (Asymptotic Analysis)

- **คำสั่งพื้นฐาน** = คำสั่งที่ใช้เวลาคงตัว ไม่ขึ้นกับปริมาณข้อมูล เช่น `= + - * / % == != < > return`, `Math.max(a,b)`
- วิเคราะห์โดยหา **ฟังก์ชันจำนวนครั้งที่คำสั่งพื้นฐานทำงาน** แล้วดู **อัตราการเติบโต**
- 📌 **"ฟังก์ชันที่โตช้ากว่า = มีประสิทธิภาพดีกว่า"**

### ตาราง Growth Rates

| สัญกรณ์ | ชื่อ | เพิ่ม input 2 เท่า → เวลาเพิ่ม | ตัวอย่าง |
|---|---|---|---|
| O(1) | constant | เท่าเดิม | เข้าถึง `arr[5]`, push/pop |
| O(log n) | logarithmic | เพิ่มทีละนิด | Binary search |
| O(n) | linear | 2 เท่า | loop เดียว, Sequential search |
| O(n log n) | — | มากกว่า 2 เท่าเล็กน้อย | Merge sort |
| O(n²) | quadratic | **4 เท่า** | 2-nested loop, หาค่าซ้ำใน array |
| O(n³) | cubic | **8 เท่า** | 3-nested loop, matrix multiplication |

# บทที่ 2 · Array — สูตรคำนวณ Address (ตรงกับใบงานที่ 1)

## 2.1 อาเรย์ 1 มิติ

$$\text{LOC}(A[i]) = L_0 + c \times (i - b)$$

| ตัวแปร | ความหมาย |
|---|---|
| $L_0$ | address ของตำแหน่งที่ **ทราบค่า** |
| $c$ | ขนาดของสมาชิกแต่ละตัว (ไบต์/บิท) |
| $i$ | index ของสมาชิกที่ต้องการหา |
| $b$ | index ของตำแหน่งที่ทราบค่า ($L_0$) |

> ถ้าโจทย์ให้ base address ที่ `A[0]` → $b = 0$ สูตรจะเหลือ $L_0 + c \times i$

## 2.2 อาเรย์ 2 มิติ — ขนาด M × N (M = จำนวนแถว, N = จำนวนคอลัมน์)

### Row Major (แถวเป็นหลัก — วางทีละแถว)

| กรณี | สูตร |
|---|---|
| ทราบ $L_0$ ที่ `a[0][0]` | $\text{LOC}(B[I][J]) = L_0 + [(I \times N) + J] \times c$ |
| ทราบ $L_0$ ที่ `a[x][y]` | $\text{LOC}(B[I][J]) = L_0 + [(I-x) \times N + (J-y)] \times c$ |

### Column Major (คอลัมน์เป็นหลัก — วางทีละคอลัมน์)

| กรณี | สูตร |
|---|---|
| ทราบ $L_0$ ที่ `a[0][0]` | $\text{LOC}(B[I][J]) = L_0 + [(J \times M) + I] \times c$ |
| ทราบ $L_0$ ที่ `a[x][y]` | $\text{LOC}(B[I][J]) = L_0 + [(J-y) \times M + (I-x)] \times c$ |

### 🔑 วิธีจำที่ไม่มีวันสับสน

```
Row major    → นับ "แถวที่ผ่านมาก่อนหน้า"  → คูณด้วย N (จำนวนคอลัมน์)
Column major → นับ "คอลัมน์ที่ผ่านมาก่อนหน้า" → คูณด้วย M (จำนวนแถว)
```
ตัวคูณจะเป็น "จำนวนสมาชิกใน 1 แถว/คอลัมน์" เสมอ → **Row ใช้ N, Column ใช้ M**

## 2.3 ขั้นตอนทำข้อสอบ (ทำตามนี้ทุกข้อ ได้คะแนนวิธีทำ)

1. เขียนสูตรตั้งต้นก่อน
2. เขียนกำกับว่าโจทย์ให้ค่าอะไรบ้าง: $M, N, c, L_0, x, y, I, J$
3. แทนค่าลงสูตร (โชว์ทุกบรรทัด)
4. คิดในวงเล็บ → คูณ → บวก
5. สรุปคำตอบ

## 2.4 เฉลยใบงานที่ 1 (ตรวจแล้ว ✓ ถูกทั้งหมด)

| ข้อ | โจทย์ | วิธีทำ | คำตอบ |
|---|---|---|---|
| 1.1 | A[5]=80, c=2, หา A[10] | 80 + 2(10−5) | **90** |
| 1.2 | หา A[21] | 80 + 2(21−5) = 80+32 | **112** |
| 2.1 | 10×20 Row, B[0][0]=100, c=2, หา B[5][1] | 100 + [(5×20)+1]×2 = 100+202 | **302** |
| 2.2 | 20×10 Row, หา B[10][6] | 100 + [(10×10)+6]×2 = 100+212 | **312** |
| 3.1 | 10×20 Column (M=10), หา B[5][1] | 100 + [(1×10)+5]×2 = 100+30 | **130** |
| 3.2 | 20×10 Column (M=20), หา B[10][6] | 100 + [(6×20)+10]×2 = 100+260 | **360** |
| 4 | C 79×81 Column, c=4, C[0][0]=1024, หา C[61][18] | 1024 + 4[(18×79)+61] = 1024+4(1483) | **6,956** |
| 5 | D 51×47 Row, c=4, D[21][37]=6976, หา D[1][1] | 6976 + 4[(1−21)×47 + (1−37)] = 6976 − 3904 | **3,072** |

⚠️ **จุดพลาดบ่อย:** ข้อ 5 ผลลัพธ์ในวงเล็บติดลบ (เพราะย้อนกลับไปตำแหน่งก่อนหน้า) → คำตอบต้อง **น้อยกว่า** $L_0$ ถ้าได้มากกว่าแปลว่าคิดผิด

# บทที่ 3 · Stack (Assignment 2)

## 3.1 คุณสมบัติพื้นฐาน

- **LIFO** (Last In First Out) — เข้าทีหลังออกก่อน
- ทำงานที่ปลายเดียวคือ **TOP**
- `push(x)` = ใส่ข้อมูล → TOP + 1 · `pop()` = นำข้อมูลออก → TOP − 1
- **สแตกว่าง: TOP = −1**
- **Overflow** = push ตอนเต็ม · **Underflow** = pop ตอนว่าง

> 📌 ข้อสอบมักให้วาดรูปสแตกทีละคำสั่ง แล้วถามท้ายว่า TOP ชี้ตำแหน่งไหน / S[TOP] เก็บค่าอะไร
> **pop ตอนว่าง = ไม่มีอะไรเกิดขึ้น TOP ยังคงเป็น −1 (เขียน TOP = −1 กำกับไว้ให้ชัด)**

## 3.2 ลำดับความสำคัญของโอเปอเรเตอร์

| ลำดับ | เครื่องหมาย |
|---|---|
| สูงสุด | `^` (ยกกำลัง) |
| กลาง | `*` `/` |
| ต่ำสุด | `+` `−` |
| พิเศษ | `(` `)` — จัดการแยกตามกฎ |

## 3.3 กฎการแปลง Infix → Postfix (5 ข้อ ท่องให้ได้)

1. ถ้าข้อมูลเข้าเป็น **Operand** → ส่งออกไปเป็นผลลัพธ์ทันที
2. ถ้าข้อมูลเข้าเป็น **Operator**
   - 2.1 สแตกว่าง → `push(Op_new)`
   - 2.2 สแตกไม่ว่าง → เทียบ `Op_new` กับ `Op_top`
     - **สำคัญกว่า** → `push(Op_new)`
     - **น้อยกว่าหรือเท่ากับ** → `pop()` ออกไปเป็นผลลัพธ์ แล้วเทียบกับตัวถัดไปเรื่อย ๆ จนกว่า `Op_new` จะสำคัญกว่า แล้วจึง `push(Op_new)`
3. ข้อมูลเข้าเป็น `(` → `push("(")`
4. ข้อมูลเข้าเป็น `)` → `pop()` ออกไปเป็นผลลัพธ์ **จนกว่าจะถึง `(`** แล้วทิ้งวงเล็บทั้งคู่
5. ข้อมูลเข้าหมด → `pop()` ออกให้หมดจนสแตกว่าง

⚠️ **จุดสำคัญ:** `(` ในสแตกไม่ถือเป็น operator → เจอ `(` ให้หยุดเทียบทันที แล้ว push ตัวใหม่ลงไป

⚠️ **กรณี `^` ติดกัน** (เช่น `G ^ H ^ I`) ยกกำลังทำจาก **ขวาไปซ้าย** → คิดเป็น `G ^ (H ^ I)` (ตรงกับ expression tree ใน Assignment 4 ข้อ 4.1)

## 3.4 การหาค่านิพจน์ Postfix

1. เจอ **Operand** → `push`
2. เจอ **Operator** → `pop()` ออกมา **2 ตัว** คำนวณแล้ว `push` ผลลัพธ์กลับ
3. ข้อมูลหมด → `pop` ตัวสุดท้าย = คำตอบ

🚨 **ลำดับตัวถูกดำเนินการ (พลาดกันเยอะที่สุด)**
```
pop ครั้งที่ 1 ได้ b   (ตัวหลัง)
pop ครั้งที่ 2 ได้ a   (ตัวหน้า)
ผลลัพธ์ = a (op) b     ← ห้ามสลับ!
```
เช่น `10 3 −` → pop ได้ 3 แล้วได้ 10 → คำตอบ **10 − 3 = 7** (ไม่ใช่ 3 − 10)
สำคัญมากกับ `−` `/` `^` (ส่วน `+` `*` สลับได้ไม่ผิด)

## 3.5 เฉลย Assignment 2 (ตรวจแล้ว ✓)

**กิจกรรมที่ 1 (สแตก 14 คำสั่ง):** TOP = **1**, S[TOP] = **n**

**กิจกรรมที่ 2.1** `A / C * B – X * Y + R - D`
→ Postfix = **`A C / B * X Y * − R + D −`**

**กิจกรรมที่ 2.2** `( ( G + F ) * T ) + B - ( M ^ N )`
→ Postfix = **`G F + T * B + M N ^ −`**

**กิจกรรมที่ 3.1** `A C * B F D - ^ + E +` (A=10, B=3, C=7, D=11, E=2, F=15)

| ขั้น | คำนวณ | Stack |
|---|---|---|
| `A C *` | 10 × 7 = 70 | 70 |
| `B F D -` | 15 − 11 = 4 | 70, 3, 4 |
| `^` | 3 ^ 4 = 81 | 70, 81 |
| `+` | 70 + 81 = 151 | 151 |
| `E +` | 151 + 2 = **153** | 153 |

**กิจกรรมที่ 3.2** `M N D + ^ U P Q – C L ^ * - /` (C=2, D=0, L=1, M=4, N=3, P=8, Q=5, U=10)

| ขั้น | คำนวณ | Stack |
|---|---|---|
| `N D +` | 3 + 0 = 3 | 4, 3 |
| `^` | 4 ^ 3 = 64 | 64 |
| `P Q −` | 8 − 5 = 3 | 64, 10, 3 |
| `C L ^` | 2 ^ 1 = 2 | 64, 10, 3, 2 |
| `*` | 3 × 2 = 6 | 64, 10, 6 |
| `−` | 10 − 6 = 4 | 64, 4 |
| `/` | 64 ÷ 4 = **16** | 16 |

# บทที่ 4 · Queue (Assignment 3)

## 4.1 คุณสมบัติพื้นฐาน

- **FIFO** (First In First Out) — เข้าก่อนออกก่อน
- ตัวแปรควบคุม 2 ตัว: **front (F)** ชี้ตำแหน่งแรกของข้อมูล · **back (B)** ชี้ตำแหน่งสุดท้าย
- **คิวว่าง → F = B = −1**
- `enqueue` = นำข้อมูลเข้า (ที่ back) · `dequeue` = นำข้อมูลออก (ที่ front)

## 4.2 คิวทั้ง 3 แบบ

### แบบที่ 1 · คิวแบบตรึงหัวคิว (Fixed Front)

- **F ตรึงอยู่ที่ตำแหน่ง 0 เสมอ**
- **นำเข้า:** B ขยับไป 1 ตำแหน่ง แล้วใส่ข้อมูล
- **นำออก:** เอาข้อมูลที่ F ออก แล้ว **เลื่อนข้อมูลที่เหลือทั้งหมดมาข้างหน้า 1 ช่อง** → B ลดลง 1
- **เต็มเมื่อ** B อยู่ตำแหน่งสุดท้ายของอาเรย์ (B = N−1)
- ⏱️ enqueue **O(1)** / dequeue **O(n)**
- ข้อจำกัด: ถ้าข้อมูลเยอะและนำออกบ่อย จะช้ามาก

### แบบที่ 2 · คิวแบบไม่ตรึงหัวคิว (Linear Queue)

- **นำออกโดยขยับ F ไปข้างหน้า** แทนการเลื่อนข้อมูล → เร็วขึ้น
- **นำเข้า:** B = B + 1 แล้ว `Q[B] = item` (ถ้า F = −1 ให้ตั้ง F = 0 ก่อน)
- **นำออก:** `item = Q[F]` → ถ้าเหลือตัวเดียว (F = B) ให้ F = B = −1, ถ้าไม่ใช่ F = F + 1
- **เต็มเมื่อ B = N−1** ← แม้ด้านหน้าจะยังว่างก็ใส่ไม่ได้ (**เกิด Overflow ทั้งที่คิวไม่เต็มจริง**)
- ⏱️ enqueue **O(1)** / dequeue **O(1)**
- ข้อเสีย: **เสียพื้นที่ด้านหน้าไปเปล่า ๆ**

### แบบที่ 3 · คิววงกลม (Circular Queue)

นำพื้นที่ว่างด้านหน้ากลับมาใช้ใหม่ ← แก้ปัญหาของแบบที่ 2

**สูตรหลักที่ต้องเขียนกำกับในข้อสอบ:**
```
B = (B + 1) mod N       ← ขยับ back
F = (F + 1) mod N       ← ขยับ front
```

| การทำงาน | เงื่อนไข |
|---|---|
| **ตรวจสอบเต็ม** (ก่อน enqueue) | คำนวณ `newBack = (B+1) mod N` → ถ้า **newBack = F แปลว่าเต็ม (Overflow)** ใส่ไม่ได้ |
| ถ้าไม่เต็ม | `B = newBack` แล้ว `Q[B] = item` |
| **ตรวจสอบว่าง** (ก่อน dequeue) | ถ้า F = −1 หรือ B = −1 → คิวว่าง (Underflow) |
| dequeue ปกติ | `item = Q[F]` → `F = (F+1) mod N` |
| dequeue ตัวสุดท้าย (F = B) | → **F = −1, B = −1** (กลับเป็นคิวว่าง) |

> ⚠️ คิววงกลมจะเหลือช่องว่าง **1 ช่องเสมอ** ตอนที่ถือว่า "เต็ม" (เพื่อแยกสถานะเต็มกับว่าง)

## 4.3 ตารางเปรียบเทียบ (ออกสอบเป็นข้อเขียนสั้นบ่อย)

| ชนิดคิว | นำข้อมูลเข้า | นำข้อมูลออก | จุดเด่น/จุดด้อย |
|---|---|---|---|
| ตรึงหัวคิว | O(1) | **O(n)** | ไม่เสียพื้นที่ แต่ต้องเลื่อนข้อมูลทุกครั้ง |
| ไม่ตรึงหัวคิว | O(1) | O(1) | เร็ว แต่เสียพื้นที่ด้านหน้าถาวร |
| วงกลม | O(1) | O(1) | เร็ว + ใช้พื้นที่คุ้ม (ดีที่สุด) |

## 4.4 เทคนิคทำข้อวาดรูป

1. เขียน N (ขนาดอาเรย์) ไว้มุมกระดาษ และเขียนสูตร `F=(F+1) mod N`, `B=(B+1) mod N` กำกับไว้ (ได้คะแนนวิธีคิด)
2. ทำทีละคำสั่ง **อย่าข้าม** — วาดครบทุกช่อง แล้วเขียนลูกศร F, B ทุกครั้ง
3. คิวไม่ตรึง/วงกลม: ข้อมูลที่ถูกลบแล้ว **ให้ลบออกจากช่อง** (คิววงกลม) หรือ **ปล่อยค่าเดิมค้างไว้แต่ไม่นับ** (คิวไม่ตรึงหัวคิว — ตามที่อาจารย์วาดในเฉลย)
4. ถ้าเกิด Overflow → **เขียนกำกับว่า "เกิด Overflow" แล้ววาดรูปเดิมซ้ำ** (สถานะไม่เปลี่ยน) — ข้อนี้มีคะแนน

## 4.5 เฉลย Assignment 3 (ตรวจแล้ว ✓ ถูกทั้งหมด)

| ข้อ | ชนิดคิว | F | Q[F] | B | Q[B] | หมายเหตุ |
|---|---|---|---|---|---|---|
| 1 | ตรึงหัวคิว | 0 | e | 2 | g | F ตรึงที่ 0 เสมอ |
| 2 | ไม่ตรึงหัวคิว | 4 | e | 5 | h | **insert(g) เกิด Overflow** |
| 3 | Circular (N=6) | 4 | e | 0 | g | B วนกลับมาที่ 0 |
| 4 | Circular (N=10) | 8 | i | 2 | m | B วนจาก 9 → 0 → 1 → 2 |
| 5 | Circular (N=8) | 3 | b | 2 | k | **insert(m) เกิด Overflow** |

**ข้อ 5 อธิบายจุด Overflow:** ก่อน `insert(m)` มี F = 3, B = 2 → `newBack = (2+1) mod 8 = 3` ซึ่ง **เท่ากับ F พอดี** → คิวเต็ม ใส่ไม่ได้

# บทที่ 5 · Dynamic Array *(ไม่รวม Amortized Analysis ตามขอบเขต)*

## 5.1 Dynamic Array คืออะไร

อาเรย์ที่ **ขยายขนาดตัวเองได้อัตโนมัติ** เมื่อข้อมูลเริ่มเต็มพื้นที่
- Python → `list` · Java → `ArrayList` · C++ → `std::vector`
- คอมพิวเตอร์ **ขยายพื้นที่เดิมตรง ๆ ไม่ได้** เพราะพื้นที่ข้าง ๆ อาจมีโปรแกรมอื่นจองอยู่

## 5.2 กระบวนการทำงานเมื่อข้อมูลเต็ม (4 ขั้นตอน — ออกสอบเป็นข้อเขียน)

1. **สร้างบ้านใหม่** — จองพื้นที่ใน RAM ชุดใหม่ที่ใหญ่กว่าเดิม (โดยทั่วไป **ใหญ่เป็น 2 เท่า**)
2. **ย้ายของ** — คัดลอกข้อมูลทั้งหมดจากอาเรย์เก่าไปอาเรย์ใหม่
3. **ทุบบ้านเก่า** — คืนพื้นที่อาเรย์เก่าให้ระบบ (Garbage Collection / Free Memory)
4. **ใส่ข้อมูลใหม่** — นำข้อมูลตัวใหม่ใส่ลงช่องว่างถัดไป

## 5.3 ความเร็วในการทำงาน

| การทำงาน | Time Complexity | อธิบาย |
|---|---|---|
| Access | **O(1)** | รู้ตำแหน่งแน่นอน ระบุ index ได้เลย |
| Insert / Delete **ท้ายอาเรย์** | **O(1)** | เร็ว ยกเว้นรอบที่ต้องขยายขนาด |
| Insert / Delete **ระหว่างทาง** | **O(n)** | ต้องขยับข้อมูลตัวอื่นหลบให้ |
| Search | **O(n)** | ต้องไล่ดูทีละช่องตั้งแต่ต้นจนเจอ |

## 5.4 ข้อดี / ข้อจำกัด

**ข้อดี**
- **ยืดหยุ่นสูง** — ไม่ต้องคาดเดาปริมาณข้อมูลตั้งแต่ตอนเขียนโปรแกรม
- **เข้าถึงข้อมูลเร็ว O(1)** — ข้อมูลยังเรียงติดกันในหน่วยความจำ ระบุ index ได้ทันที

**ข้อจำกัด**
- **การขยายขนาดมีต้นทุน O(n)** — จังหวะที่ต้องคัดลอกข้อมูลทั้งหมด โปรแกรมจะช้าลง
- **เปลืองแรม (Wasted Space)** — ขยายเป็น 100 ช่องแต่ใช้จริง 51 ช่อง อีก 49 ช่องถูกจองไว้เฉย ๆ

# บทที่ 6 · Linked List — Single & Double
## ⭐ บทนี้ออกสอบแบบ "เขียนคำสั่ง" — ต้องจำคำสั่งให้ได้เป๊ะ

## 6.1 โครงสร้างพื้นฐาน

**Linked List** = เก็บข้อมูลโดยเชื่อมโยงตำแหน่งต่อกันไป สมาชิกแต่ละตัวเรียกว่า **โหนด (node)**

| ประเภท | ส่วนประกอบของโหนด |
|---|---|
| **Single Linked List** | `item` (ข้อมูล) + `link` (ที่อยู่โหนดถัดไป) — **2 ส่วน** |
| **Double Linked List** | `Llink` (โหนดก่อนหน้า) + `item` + `Rlink` (โหนดถัดไป) — **3 ส่วน** |

### คลาส Node (Single)
```java
private Object item;
private Node link;

public Node() { link = null; }                     // head node
public Node(Object newItem) {                       // last node
    item = newItem;  link = null;
}
public Node(Object newItem, Node nextNode) {        // node ใด ๆ
    item = newItem;  link = nextNode;
}
```
เมธอด: `getItem() / setItem()` , `getLink() / setLink()`

### คลาส DNode (Double)
```java
private Object item;
private DNode Rlink;
private DNode Llink;

public DNode() { Rlink = null; Llink = null; }                  // head node
public DNode(Object newItem) {                                   // node ไม่มีลิงก์
    item = newItem;  Rlink = null;  Llink = null;
}
public DNode(Object newItem, DNode nextNode, DNode prevNode) {
    item = newItem;  Rlink = nextNode;  Llink = prevNode;
}
```
เมธอด: `setRlink() / getRlink()` , `setLlink() / getLlink()` , `setItem() / getItem()`

### การสร้างลิงค์ลิสต์
```java
// Single                          // Double
Node head = new Node();            DNode head = new DNode();
Node newNode = new Node(item);     DNode newNode = new DNode(item);
```

## 6.2 การค้นหาตำแหน่ง (ต้องทำก่อนแทรก/ลบเสมอ)

| ตัวแปร | หน้าที่ | ใช้ใน |
|---|---|---|
| `curr` | ชี้โหนดที่กำลังพิจารณา / โหนดที่ต้องการ | Single + Double |
| `prev` | ชี้โหนด**ก่อนหน้า** `curr` | Single + Double |
| `next` | ชี้โหนด**ถัดจาก** `curr` | **Double เท่านั้น** |

**คำสั่งค้นหา (Single Linked List)**
```java
curr = head;
while ((curr.getItem() != item) && (curr != null)) {
    prev = curr;
    curr = curr.getLink();
}
```
- ค้นหาตั้งแต่ตำแหน่งแรกไปเรื่อย ๆ จนพบ หรือถึงสมาชิกตัวสุดท้าย
- **ถ้าไม่พบ → `curr` จะมีค่าเป็น `null`**

**Double Linked List** เพิ่มการเก็บโหนดถัดไป
```java
next = curr.getRlink();
prev = curr.getLlink();
```

---

## 6.3 🔥 SINGLE LINKED LIST — คำสั่งแทรก / ลบ (สรุปตาราง)

### การแทรกโหนด (3 กรณี)

| กรณี | คำสั่ง |
|---|---|
| **แทรกระหว่างข้อมูลที่มีอยู่** | `Node newNode = new Node(item);`<br>`newNode.setLink(curr);`<br>`prev.setLink(newNode);` |
| **แทรกที่ตำแหน่งแรก** | `Node newNode = new Node(item);`<br>`newNode.setLink(curr);`<br>`head.setLink(newNode);`  ← *(กรณีมี head node นำหน้า)* |
| **เพิ่มที่ตำแหน่งสุดท้าย** | ค้นหาจนสุดลิสต์ (prev = โหนดสุดท้าย, curr = null)<br>`Node newNode = new Node(item);`<br>`prev.setLink(newNode);` |

### การลบโหนด (3 กรณี)

| กรณี | คำสั่ง |
|---|---|
| **ลบโหนดที่อยู่ระหว่างข้อมูล** | `prev.setLink(curr.getLink());` |
| **ลบโหนดตำแหน่งแรก** | `head = curr.getLink();` |
| **ลบโหนดตำแหน่งสุดท้าย** | `prev.setLink(null);` |

### 🧠 หลักคิดของ Single Linked List
```
แทรก → ต่อลิงก์ของโหนดใหม่ก่อน (newNode.setLink(curr))
        แล้วค่อยเปลี่ยนลิงก์ของโหนดเดิม (prev.setLink(newNode))
        ***ห้ามสลับลำดับ ไม่งั้นลิสต์ขาด***

ลบ   → ให้ prev ข้ามโหนด curr ไปเลย
```

---

## 6.4 🔥 DOUBLE LINKED LIST — คำสั่งแทรก / ลบ (สรุปตาราง)

### การแทรกโหนด (3 กรณี)

**① แทรกระหว่างข้อมูลที่มีอยู่ (4 Steps)**
```java
Step 1: DNode newNode = new DNode(item);
Step 2: newNode.setRlink(curr);      // ต่อขวาไปหา curr
        newNode.setLlink(prev);      // ต่อซ้ายไปหา prev
Step 3: prev.setRlink(newNode);      // prev หันขวามาหาโหนดใหม่
Step 4: curr.setLlink(newNode);      // curr หันซ้ายมาหาโหนดใหม่
```

**② แทรกที่ตำแหน่งแรก (4 Steps)**
```java
Step 1: DNode newNode = new DNode(item);
Step 2: newNode.setRlink(curr);
Step 3: curr.setLlink(newNode);
Step 4: head = newNode;              // อัพเดต head ให้ชี้โหนดใหม่
```

**③ เพิ่มที่ตำแหน่งสุดท้าย (3 Steps)**
```java
Step 1: DNode newNode = new DNode(item);
Step 2: newNode.setLlink(prev);      // ต่อซ้ายไปหาโหนดสุดท้ายเดิม
Step 3: prev.setRlink(newNode);      // โหนดสุดท้ายเดิมหันขวามาหาโหนดใหม่
```
*(Rlink ของ newNode เป็น null อยู่แล้วจาก constructor)*

### การลบโหนด (3 กรณี)

**① ลบโหนดที่อยู่ระหว่างข้อมูล**
```java
Step 1: prev.setRlink(next);         // ข้าม curr ไปทางขวา
Step 2: next.setLlink(prev);         // ข้าม curr ไปทางซ้าย
```

**② ลบโหนดตำแหน่งแรก**
```java
Step 1: head = next;                 // head ชี้โหนดถัดไป
Step 2: next.setLlink(null);         // ตัดลิงก์ซ้ายของโหนดใหม่
```

**③ ลบโหนดตำแหน่งสุดท้าย**
```java
Step 1: prev.setRlink(null);         // prev กลายเป็นโหนดสุดท้ายแทน
```

### 🧠 หลักคิดของ Double Linked List
```
"อะไรที่ทำกับ Rlink ต้องทำกับ Llink ด้วยเสมอ"   ← จำประโยคเดียวนี้พอ

แทรก = 4 คำสั่ง (newNode 2 ข้าง + เพื่อนบ้าน 2 ตัว)   ยกเว้นแทรกท้าย/แรก = 3 คำสั่ง
ลบ    = 2 คำสั่ง (เพื่อนบ้านซ้าย-ขวาจับมือกันเอง)      ยกเว้นลบท้าย = 1 คำสั่ง
```

## 6.5 ตารางเทียบ Single vs Double (ท่องก่อนเข้าห้องสอบ)

| ตำแหน่ง | Single | Double |
|---|---|---|
| แทรกแรก | `newNode.setLink(curr);`<br>`head.setLink(newNode);` | `newNode.setRlink(curr);`<br>`curr.setLlink(newNode);`<br>`head = newNode;` |
| แทรกกลาง | `newNode.setLink(curr);`<br>`prev.setLink(newNode);` | `newNode.setRlink(curr);`<br>`newNode.setLlink(prev);`<br>`prev.setRlink(newNode);`<br>`curr.setLlink(newNode);` |
| แทรกท้าย | `prev.setLink(newNode);` | `newNode.setLlink(prev);`<br>`prev.setRlink(newNode);` |
| ลบแรก | `head = curr.getLink();` | `head = next;`<br>`next.setLlink(null);` |
| ลบกลาง | `prev.setLink(curr.getLink());` | `prev.setRlink(next);`<br>`next.setLlink(prev);` |
| ลบท้าย | `prev.setLink(null);` | `prev.setRlink(null);` |

> 💡 **เวลาตอบข้อสอบ:** ควรเขียน (1) ขั้นตอนค้นหาตำแหน่งด้วย curr/prev ก่อน แล้ว (2) คำสั่งสร้างโหนด แล้ว (3) คำสั่งปรับลิงก์ตามลำดับ พร้อมวาดรูปลูกศรกำกับ จะได้คะแนนเต็มกว่าเขียนแค่บรรทัดเดียว

# บทที่ 7 · Tree (Assignment 4 + ไฟล์เสริม)

## 7.1 ศัพท์ที่ต้องรู้ (Tree Terminology)

| ศัพท์ | ความหมาย |
|---|---|
| **Node** | ทำหน้าที่เก็บข้อมูล |
| **Branch** | เส้นเชื่อม node เข้าด้วยกัน แสดงความสัมพันธ์ |
| **Root node** | โหนดตำแหน่งบนสุดของทรี |
| **Parent / Child** | โหนดด้านบน = แม่, โหนดด้านล่างที่ติดกัน = ลูก |
| **Leaf node** | โหนดล่างสุดที่ไม่มีลูก |
| **Level** | ระยะทางจาก Root |
| **Depth** | ความยาว path จาก root ถึง node นั้น (**root มี depth = 0**) |
| **Degree** | จำนวน branch ที่สัมพันธ์กับ node |
| **Indegree** | จำนวน branch ที่**เข้าหา** node (มาจาก level ก่อนหน้า) |
| **Outdegree** | จำนวน branch ที่**ออกจาก** node ไป level ที่ต่ำกว่า |
| **Subtree** | โครงสร้างที่เชื่อมต่อกันภายใต้ Root โดย node แรกเป็น root ของ subtree นั้น |

📌 **ข้อสังเกต:** โหนด level บนสุด (root) มี **indegree = 0** · โหนด level ล่างสุด (leaf) มี **outdegree = 0**

## 7.2 ประเภทของ Binary Tree

| ประเภท | นิยาม |
|---|---|
| **Binary Tree** | ต้นไม้ที่แต่ละ node มี **outdegree ไม่เกิน 2** |
| **Complete Binary Tree** | binary tree ที่มี node **เต็มทุก level** |
| **Nearly Complete Binary Tree** | เต็มทุก level ยกเว้น level สุดท้าย และ node ใน level สุดท้าย**เรียงชิดซ้าย** |
| **General Tree** | ทรีที่มี outdegree ได้ไม่จำกัดจำนวน |

## 7.3 การเก็บ Binary Tree

### เก็บลงใน Array (เรียงจาก root ลงทีละ level, ใน level เดียวกันเรียงซ้าย→ขวา)
```
โหนดที่ตำแหน่ง i  →  ลูกซ้าย = 2i + 1     ลูกขวา = 2i + 2
โหนดที่ตำแหน่ง i  →  พ่อแม่  = (i − 1) / 2   (ปัดเศษทิ้งเสมอ)
```

### เก็บลงใน Linked List
ใช้โครงสร้างแบบ **Double Linked List** → `LCHILD | DATA | RCHILD`
(ลูกซ้ายเก็บที่ลิงก์ซ้าย, ลูกขวาเก็บที่ลิงก์ขวา)

## 7.4 การแปลง General Tree → Binary Tree ⭐ (Assignment 4 ข้อ 1)

**3 ขั้นตอน**
1. ระบุ **Child ที่อยู่ซ้ายสุด**
2. **เชื่อมโหนดพี่น้อง** ที่มีโหนดแม่เดียวกันเข้าด้วยกัน เรียงจากซ้ายไปขวา
3. **ลบ Branch ที่ไม่ต้องการ**

**หลักการสรุปสั้น ๆ (ใช้ตอนสอบ)**
```
โหนดด้านซ้าย  = ลูกคนโต (ลูกที่อยู่ซ้ายสุด)
โหนดด้านขวา  = น้องคนถัดไป (พี่น้องระดับเดียวกัน)
```
> พิจารณาไล่ทีละโหนด เริ่มจาก Root

## 7.5 การท่องทรี (Tree Traversal)

### Depth-First (3 แบบ)

| แบบ | ลำดับ | สูตรย่อ |
|---|---|---|
| **Preorder** | Root → Left → Right | **N–L–R** |
| **Inorder** | Left → Root → Right | **L–N–R** |
| **Postorder** | Left → Right → Root | **L–R–N** |

> 💡 **เทคนิควงกลม subtree** (แบบที่ใช้ใน Assignment 4): วงกลมครอบ subtree แล้วเขียนลำดับของ subtree นั้นไว้ข้าง ๆ ค่อย ๆ แตกลงไปทีละชั้น จะไม่หลง
>
> 💡 **Inorder ของ BST → ได้ข้อมูลเรียงจากน้อยไปมากเสมอ** (ใช้ตรวจคำตอบตัวเอง)

**Preorder ด้วย Stack (ถ้าโจทย์ให้แสดงขั้นตอน)**
1. Push Root node ลง stack
2. Pop โหนดออกจากสแต็ก → นำไปต่อลำดับผลลัพธ์
3. Push โหนดลูก **ทางขวาก่อน แล้วตามด้วยซ้าย** (เพื่อให้ซ้ายถูก pop ก่อน)
4. ทำซ้ำข้อ 2–3 จนกว่าสแต็กจะว่าง

### Breadth-First (ใช้คิว) ⭐ (Assignment 4 ข้อ 3)

**ขั้นตอน**
1. เริ่มจากโหนดบนสุด นำ**โหนดลูกใส่คิว**ตามลำดับ ซ้ายก่อนแล้วขวา
2. เมื่อใส่ลูกครบทั้งซ้ายขวาแล้ว **นำข้อมูลออกจากคิว** มาพิจารณาต่อ
3. ทำซ้ำข้อ 1–2 จนข้อมูลในคิวหมด

**รูปแบบตารางที่ต้องเขียน**

| Dequeue | Enqueue | Queue |
|---|---|---|
| – | A | A |
| A | B | B |
| B | E, C | E, C |
| … | … | … |

📌 ผลลัพธ์ = **ประมวลผลทีละ Level จากบนลงล่าง ใน level เดียวกันไล่ซ้ายไปขวา**

## 7.6 Binary Search Tree (BST) ⭐ (Assignment 4 ข้อ 5)

**กฎการเก็บข้อมูล (ตามสไลด์)**
1. **Root** คือข้อมูลตัวแรกที่อ่านเข้ามา
2. ข้อมูลตัวถัดมา **มากกว่าหรือเท่ากับ** → ไปเป็นลูกฝั่ง **ขวา** · **น้อยกว่า** → ไปเป็นลูกฝั่ง **ซ้าย**
3. ถ้าตำแหน่งนั้นมีค่าอยู่แล้ว → **เปรียบเทียบซ้ำกับโหนดนั้น** แล้วลงซ้าย/ขวาต่อไป

> ⚠️ ต้องเทียบไล่ลงไป**ทีละโหนดจาก root** เสมอ ห้ามเดาตำแหน่ง

## 7.7 Expression Tree ⭐ (Assignment 4 ข้อ 4)

**คุณสมบัติ**
- **Leaf** เก็บ **Operand**
- **Root และ Internal node** เก็บ **Operator**
- **Subtree** = sub expression

**ความสัมพันธ์กับนิพจน์ (ออกสอบแน่นอน)**

| การท่อง | ได้นิพจน์ |
|---|---|
| **Preorder** Traversal | **Prefix** Expression |
| **Inorder** Traversal | **Infix** Expression |
| **Postorder** Traversal | **Postfix** Expression |

**วิธีสร้าง Expression Tree**
1. หา operator ที่ทำ **ทีหลังสุด** (ลำดับความสำคัญต่ำสุด และอยู่นอกวงเล็บ) → เป็น **Root**
2. นิพจน์ด้านซ้ายของ operator นั้น → subtree ซ้าย · ด้านขวา → subtree ขวา
3. ทำซ้ำกับแต่ละ subtree จนเหลือแต่ operand เป็น leaf

> ⚠️ `^` เชื่อมจาก **ขวาไปซ้าย** → `G ^ H ^ I` = `G ^ (H ^ I)` (ตัว `^` ตัวซ้ายอยู่บนกว่า)

## 7.8 การสร้างทรีจาก Preorder + Inorder ⭐⭐ (ไฟล์เสริม)

**หลักการ**
- **Preorder** → บอกว่าใครเป็น **root** ของแต่ละ subtree (ตัวแรกที่เจอ)
- **Inorder** → ทำหน้าที่ **แบ่งโหนดซ้าย-ขวา** ออกจากกัน

**ขั้นตอนทำ (ทำซ้ำแบบ recursive)**
1. หยิบตัวแรกที่ยังไม่ใช้จาก **Preorder** → เป็น root
2. ไปหาตัวนั้นใน **Inorder** → ทุกตัวที่อยู่**ซ้ายมือ** = subtree ซ้าย, ทุกตัวที่อยู่**ขวามือ** = subtree ขวา
3. กลับไปดู Preorder ตัวถัดไป → เป็น root ของ subtree ซ้าย
4. ทำซ้ำจนครบทุกโหนด

**ตัวอย่างตรวจทาน (จากไฟล์เสริมข้อ 1)**
```
Pre : P B E F D C M H I J K
In  : F E B D P C H I M K J

P เป็น root  →  In ซ้าย {F E B D} , In ขวา {C H I M K J}
Pre ถัดไป B  →  B เป็น root ของ subtree ซ้าย
             In: F E | D  →  ซ้าย {F,E} , ขวา {D}
Pre ถัดไป E  →  E เป็น root ,  In: F  →  F เป็นลูกซ้ายของ E
… ทำต่อจนครบ
```

# 📋 ภาคผนวก · เช็คลิสต์ก่อนเข้าห้องสอบ

## สูตร/กฎที่ต้องท่องได้ขึ้นใจ

```
[Array]
LOC(A[i])       = L0 + c(i − b)
Row major       = L0 + c[(I×N) + J]        | ทั่วไป: L0 + c[(I−x)N + (J−y)]
Column major    = L0 + c[(J×M) + I]        | ทั่วไป: L0 + c[(J−y)M + (I−x)]
                  M = แถว , N = คอลัมน์

[Stack]
สแตกว่าง TOP = −1
Op ใหม่ "สำคัญกว่า" → push  |  "น้อยกว่าหรือเท่ากับ" → pop ออกก่อน
postfix: pop 2 ตัว → ตัวที่ pop ทีหลังอยู่หน้า

[Queue]
คิวว่าง F = B = −1
Circular:  B = (B+1) mod N ,  F = (F+1) mod N
เต็มเมื่อ  (B+1) mod N == F
เหลือตัวเดียวแล้ว dequeue → F = B = −1

[Linked List]
Single ลบกลาง : prev.setLink(curr.getLink());
Double ลบกลาง : prev.setRlink(next); next.setLlink(prev);

[Tree]
array:  ลูก = 2i+1 , 2i+2      พ่อแม่ = (i−1)/2 ปัดเศษทิ้ง
Pre = N-L-R   In = L-N-R   Post = L-R-N
General→Binary: ซ้าย = ลูกคนโต , ขวา = น้องคนถัดไป
Expression tree: Pre→Prefix , In→Infix , Post→Postfix
```

## ❌ 10 จุดพลาดที่เสียคะแนนบ่อยที่สุด

1. **Row/Column major สลับตัวคูณ** — Row ใช้ N, Column ใช้ M (จำ: "Row นับแถว → คูณจำนวนต่อแถว = N")
2. **ลืมลบ b** ในสูตร 1 มิติ เมื่อ base address ไม่ได้อยู่ที่ index 0
3. **หาค่า postfix แล้วสลับตัวเลข** ในการลบ/หาร/ยกกำลัง
4. **infix→postfix: เจอ `(` ในสแตกแล้วยัง pop ต่อ** — ต้องหยุดทันที
5. **คิววงกลมไม่เช็ค `(B+1) mod N == F` ก่อน enqueue** → ตอบเกินไป 1 ตัวโดยไม่รู้ตัว
6. **ลืมเขียนว่าเกิด Overflow** ตอนคิวเต็ม (มีคะแนนตรงนี้)
7. **ไม่วาดลูกศร F/B ทุกขั้น** ในข้อวาดคิว
8. **Double linked list แก้ลิงก์แค่ข้างเดียว** — ต้องแก้ทั้ง Rlink และ Llink
9. **แทรกโหนดสลับลำดับคำสั่ง** → ต่อ newNode ก่อน แล้วค่อยแก้ลิงก์โหนดเดิม
10. **BST ใส่ข้อมูลโดยไม่ไล่จาก root** — ต้องเทียบทีละชั้นเสมอ
